# Datum · 3D 工业建模互动课：原型方案

> 2026-11-04 · 状态：调研和 HTML 原型已完成，等确认方向后进入开发。
> 调研报告：`reports/3D 工业建模交互学习网站调研.md`；原始笔记：`research_notes/3D 工业建模交互学习网站调研/`。

## 一句话

中文、讲概念、不绑定软件的 3D 工业建模学习网站。每个建模概念配一个能亲手操作的 3D 场景；真实物件按特征树一步步重建，可以拖回滚条、改参数、爆炸开看结构。

## 1. 为什么值得做

- **空白是真的。** 调研了 20 多个产品，没有一个同时做到「中文、概念优先、不限工具、可交互 3D、讲建模操作和特征树」。
  - 厂商学习中心（Onshape、Autodesk、MySolidWorks、Shapr3D）都绑定自家软件，形式是视频加跟做。
  - Tinkercad 只教摆放和对齐。Bartosz 这类交互长文讲的是机构和数学，不讲建模操作。
  - 国内以 B站长视频为主（腾讯课堂已于 2024-10 停运），交互式内容只在面向院校的产品里。
- **最难的东西视频讲不清。** 学习者的卡点几乎都源于没理解「模型是一张依赖图」：欠定义或过定义的草图、改了前面后面就断（拓扑命名问题）、圆角和抽壳的顺序导致失败、为了让零件不动乱加配合。
- **拆解是公认最快的进步方式，但门槛高。** 有经验的人把「拖设计树回滚条，看别人怎么建」当成提高最快的方法，可现在必须装 CAD、拿到原文件，也没人解释每一步的设计意图。
- **三种交互在 CAD 工具和学习站里都没有先例，原型已经做出来了：** 高亮这一步新生成的面、半透明预示后续特征、草图在基准面上逐步画出。
- **AI 把学习重点往「读懂、检查、修改特征树」推。** Zoo、Adam 和你自己的 text-to-CAD 都直接产出特征树或代码，会点按钮不如会读、会改。拆解加重建训练的正是这种能力。

## 3. 教学设计原则

每条后面是调研里的证据。

1. **一步一个概念。** 一节课 6–10 步，有效互动 5–10 分钟。分段的效应量约 d = 0.7–0.8。
2. **每步自动转到关键视角。** 真正起作用的是「看到关键视角或截面，并得到反馈」，不是能自由旋转（Keehner 2008）。对空间能力弱的人，不加约束的多视角反而有害。
3. **任务嵌在 3D 里。** 点平面、拖角点、拉箭头、改尺寸，控件就是任务。单独给学习者「播放 / 暂停」控制，平均收益接近 0（Karich 2014）。
4. **先猜，再看。** 结果值得预测的地方，先提问再演示（Hegarty 2003）。
5. **动画只用在「变化本身就是内容」的地方。** 拉伸、旋转、抽壳、爆炸属于这类，程序性知识上动画的效应 d = 1.06。播放时屏幕上少放文字。
6. **答错要说为什么。** 给解释的反馈效应 0.49，只给对错 0.05。
7. **策略要明着教。** 例如「先圆角再抽壳」「草图挂在基准面上，别引用模型边」。有多年经验的用户也常用低效策略，缺的是策略知识而不是命令知识（Bhavnani）。
8. **练习形式：**
   - 检索小测（g ≈ 0.50）和间隔复习。
   - 特征树排序题。
   - 改参数测试。
   - 按图建模，用体积或质量自动判分（CSWA 和 Too Tall Toby 的机制）。
9. **不做排行榜和徽章。** 它们会降低内在动机和成绩（Hanus & Fox 2015）。进度显示「先快后慢」，减少中途放弃。
10. **不承诺「学完哪个软件都会用」。** 跨软件迁移没有同行评审证据，所以用术语对照来搭桥。

- 把「杯底圆角」改到小于壁厚，左上角会出现重建提示：内圆角退化成尖角。
- 打开「剖切」，看壁厚和内圆角。
- 回滚到「抽壳1」，看哪些面是抽壳生成的。

### 6.3 工具图鉴与术语

- 18 个命令。各软件的中文叫法已按官方简中帮助核对：Fusion 帮助目录 5,862 条、Creo 12、Rhino 8、FreeCAD 翻译文件、Onshape。
- NX 和部分子类型（如 SOLIDWORKS 新版界面写「镜向」还是「镜像」）需要中文界面截图确认。
- 有几处原以为的叫法是错的，例如 Fusion 的 Rib 是「加强筋」不是「肋」，Onshape 是「肋材」，原型里已更正。

### 6.4 两个从调研里长出来的内容方向

- **失败空间本身就是课程。** 官方课程把修复当作入门能力，学习者的卡点也几乎都是重建失败；spike 里一个马克杯就有 30% 的参数组合会失败，其中一部分还不报错。离线扫描参数时，顺手把「为什么抽壳失败」「为什么合并不产生新面」整理成讲解和预测题。
- **「检查 AI 生成的模型」单元。** text-to-CAD 直接产出特征树以后，稀缺能力变成读懂、检查、修改一棵特征树，并判断它稳不稳。拆解加改参测试训练的正是这个。

## 7. 视觉与交互规范

- **设计系统：** 基于 jim-uiux 0.2.0。黑白灰加一个强调色「工程蓝」`#2759e0`，亮暗两套；Inter 加苹方；用细线，不用阴影。设计守卫已通过，例外见 `prototype/docs/DESIGN.md`。
- **视口约定：**
  - Z 轴朝上（和 Onshape、Rhino、NX、build123d 一致）。课程里专门讲 SOLIDWORKS 的 Y 轴朝上。
  - 右上角是视图方块（HTML 文字，可点），左下角是坐标轴。
  - 这一步新生成的面用强调色，后续特征半透明，欠定义草图蓝色、完全定义黑色。
  - 尺寸标注可以直接点开改。剖切面是实心填充。
- **待改进：** spike 发现 OCCT 把抽壳后的杯口算作「被修改的顶面」而不是新面。正式版用深浅两档强调色区分「新生成的面」和「被修改的面」，更准确。
- **操作模拟的主控件是 0–100% 的「生成过程」滑杆**（对应 Onshape 特征对话框里的前后混合滑块），播放按钮只是它的自动版。图鉴演示里已经加上。

## 8. 技术方案

推荐混合架构。

**前端**
- React 19、Vite 8、TypeScript、Tailwind v4、jim-uiux。
- 3D 用 three.js r187，加原型里那套轻量 CAD 视口引擎（`prototype/src/three`）：按需渲染、颜色跟主题、视图方块、标注、剖切、快照渲染。
- 暂不用 React Three Fiber：引擎需要跨页复用、自己控制渲染循环，换 R3F 收益不大，可以再议。

**几何来源分三层**

1. **默认：离线预烘焙。**
   - 每个案例用 build123d 写参数化源码。你 text-to-cad 的环境里已有 build123d 0.11；0.13 版能读内核操作历史，建议升级。
   - 每个特征导出一个 GLB，配一份 JSON 记录每个面是哪个特征新生成或修改的（用 OCCT 历史判定），再烘焙几组预设参数。
   - 每步几十 KB；浏览器里不跑 OCCT，没有 LGPL 负担，手机也流畅。
2. **改参数沙盒：先用预烘焙的参数网格。**
   - 每节课只开放 1–2 个参数滑杆（学习科学的建议），所以可以离线把参数网格全部烘焙出来。例如 2 个参数各取 6 档，共 36 个变体；按报告估算的每份 70–100 KB，全部约 2.5–3.6 MB（未实测），也可以拖到哪档再加载哪档。滑杆在网格点之间吸附，切换几乎是瞬时的，手机也能用。
   - 每个网格点都在离线时检查过：失败或几何出错的格子不隐藏，而是写成「为什么在这里失败」的讲解。这就是报告说的「失败空间本身就是课程」。
   - 真正需要连续、任意改参的地方，再上实时内核：桌面端在 Web Worker 里加载 replicad（spike 实测见下表），或者在服务器上跑 build123d 返回 GLB。等纵切片上线、确认有这个需求再定。
3. **轻量演示。**
   - 图鉴和概念课用程序化 three.js 几何（原型现状）。
   - 草图约束课换成 planegcs：137 KB，能算自由度、指出冲突约束，求解不到 3 ms。
   - 布尔演示用 Manifold（159 KB）。

**模型源码只写一份**

调研报告指出一个取舍：离线用 build123d、在线沙盒用 replicad 的话，同一个模型要写两份代码。两种统一办法：

| 方案 | 好处 | 代价 |
| --- | --- | --- |
| 全部用 build123d（推荐） | 你熟悉、和 text-to-cad 一致；选择器、操作历史、装配联接、bd_warehouse 标准件都更全；代码对照直接展示它 | 浏览器里不能实时跑；连续改参要靠参数网格或服务端 |
| 全部用 replicad（JS） | 离线烘焙（Node）和浏览器沙盒共用一份代码 | 没有阵列 API、不暴露操作历史（spike 里要自己重包）；生态和示例少很多 |

推荐 build123d：模型是内容生产的主体，写得快、写得稳比「能在浏览器里实时跑」更重要。加上参数网格以后，绝大多数课程都不需要实时内核。

**内容、部署和风险**
- **内容组织：** 课程定义写成带类型的 TS，相当于一套步骤 DSL：标题、正文、视角、任务判定、先猜再看、小测。正文用 Markdown。公开上线时，用 React Router 的预渲染给浏览页出静态 HTML，照顾 SEO。
- **部署：** 静态站，放 jim-server（Caddy）；GLB 和 wasm 走国内可访问的 CDN。本机代理慢的时候 npmjs 会卡死，装包要用 npmmirror。
- **风险与对策：**
  - 如果以后上浏览器实时内核：OCCT 内存只涨不降（反复做把手圆角后约 1 GB）→ 只在桌面端开，并定期重启 Worker。
  - OCCT 报错不说原因 → 离线扫描参数空间，界面上给人话版的「重建提示」。
  - 没做真机测试 → 下一阶段补上。

**spike 实测：如果在浏览器里实时跑 replicad（M1 Pro，Chrome）**

| 项目 | 数值 |
| --- | --- |
| replicad 内核体积（brotli） | 4.6 MB |
| 下载时间 | 快速 4G 约 5 s；慢速 4G 约 27 s |
| 初始化 | 约 0.19 s |
| 改一次参数，只重建最终模型 | 0.14 s |
| 改一次参数，7 步全部重建 | 0.4 s |
| 随机参数组合的失败率 | 约 30%（多数是杯底圆角不大于壁厚时抽壳失败） |
