# AI 对话式建模：FeatureTree 工作台

- 状态：已定稿（2026-11-05）。
  - 阶段 0 和阶段 1 已上线（Beta，`/studio`）。
  - 阶段 2 已做：参考图、「边做边学」、看图自检，以及从拆解打开。
  - 待做：真模型评测（需要 DeepSeek key）；草图约束和分享链接未做。
- 日期：2026-11-05
- 默认模型：DeepSeek `deepseek-flash`（V4.1-Flash-1017）
- 技术栈：Vercel AI SDK 7、replicad（OpenCascade WebAssembly）、现有 three.js 视口

## 一句话

学习者用中文描述要做什么，AI 调用建模工具，每次调用都成为特征树里一个真实的特征，由 OpenCascade 内核在浏览器里算出来。学习者可以回滚、拖参数、问「为什么这样做」；AI 能看到渲染出的视图，检查做得对不对。

和通用「AI 生成 3D」的区别：产出的不是一团网格，而是**能改的参数化特征树**。这正是全站在教的东西。

## 核心设计决定

### 1. 建模表示：结构化特征树，不让 AI 写代码

AI 不写 build123d 或 JS 代码，只调用工具。每次调用往特征树里加、改、删一个特征，整棵树是一份 JSON：

```json
{
  "params": { "L": 80, "W": 50, "H": 30, "t": 2, "r": 5 },
  "features": [
    { "id": "sk1", "op": "sketch", "on": "XY", "shapes": [{ "rect": { "w": "=L", "h": "=W", "center": [0, 0] } }] },
    { "id": "ex1", "op": "extrude", "sketch": "sk1", "distance": "=H" },
    { "id": "f1", "op": "fillet", "edges": { "of": "ex1", "parallel": "Z" }, "radius": "=r" },
    { "id": "sh1", "op": "shell", "remove": { "of": "ex1", "side": "end" }, "thickness": "=t" }
  ]
}
```

这样做有几个好处：

- **和全站的教学单位一致。** 一次调用就是特征树里的一行，可以直接复用拆解页的回滚、播放、新面 / 修改面着色和参数面板。
- **可靠。** 工具参数有 JSON Schema（AI SDK 7 的 strict 模式），格式错误在执行前就会被拦下。
- **能改。** 参数面板拖动时本地重算，不用再问 AI；所有数值都可以写成 `=W/2` 这样的表达式。
- **安全。** 不执行模型生成的任意代码。
- **能导出。** 同一份 JSON 可以生成 build123d Python 代码（「看代码」页、离线烘焙都能复用），也可以导出 STEP / STL。

真有特征树表达不了的形状时，再考虑加「代码特征」作为逃生口，v1 不做。

### 2. 内核在浏览器里跑

用 replicad（OpenCascade 的 WebAssembly 版）放在 Web Worker 里，按特征树 JSON 逐个特征重算。解释器写成同构的：浏览器和 Node 都能跑，Node 用来做自动评测。

- 服务器只转发对话，不碰几何，所以算力和内存不占 jim-server。
- wasm 只在 `/studio` 页按需加载，其他页面不受影响。工作台以桌面为主，手机上只读。
- spike 发现的内存只涨不降问题：内存超过阈值就回收 Worker，用特征树 JSON 重建。特征树是确定性的，重建很便宜。
- 内核失败（圆角太大、抽壳失败）时返回结构化错误：哪个特征、原因、可能的修法。AI 据此重试；界面上把失败当成讲解的机会，和拆解页的「失败组合」一个思路。

另一个方案是服务器上用 build123d 算，好处是直接复用 `ftbake`；坏处是 3.6 GB 内存的小服务器要承担所有人的 OCCT 计算，还要处理并发和隔离。不推荐。

### 3. 用语义选择器引用面和边，不用编号

AI 不能说「第 7 条边」。编号在上游改参后会变，这就是拓扑命名问题（T1 的「特征树」课讲过）。所以选择器按语义描述，每次重建时重新解析：

- 按来源：`{ "of": "ex1", "side": "end" }`，表示 ex1 生成的末端面。
- 按方向：`{ "parallel": "Z" }`、`{ "normal": "+Z" }`，含义同 CadQuery 的 `|Z` / `>Z`。
- 按几何：`{ "type": "circle", "radius": [4, 6] }`、`{ "nearest": [0, 0, 30] }`、`{ "length_gt": 10 }`。
- 可以组合。解析结果为空，或者数量和 AI 声明的 `expect` 不符时直接报错，并列出候选，让 AI 修正。

面的来源靠把 `ftbake/classify.py` 的几何判定移植到 JS：把面上的采样点投影到上一步的曲面上，判定新生成 / 修改 / 没变。这也正好给工作台的着色用。

### 4. 工具在客户端执行

服务端只声明工具的 schema（不写 `execute`）。客户端在 `onToolCall` 里把调用交给 Worker 执行，再用 `addToolOutput` 回传一个精简结果：成功与否、新特征 id、影响了多少个面、包围盒、体积、警告或错误。工具结果凑齐后，`sendAutomaticallyWhen: lastAssistantMessageIsCompleteWithToolCalls` 自动发起下一轮。

上下文按「状态」而不是「全量历史」组织：每次请求带上当前的特征树 JSON 和最近几轮对话，不带早期的工具细节。这样长会话的 token 不会一直涨，缓存命中率也高。

### 5. 视觉：自检，加参考图

- **自检**：工具 `look` 让客户端离屏渲染等轴测、前、上、右四个视图（复用 `three/snapshot.ts`，可以高亮指定特征），作为图片交给模型，比如「看起来像不像一个带把手的杯子？把手是不是在侧面？」。
- **参考图**：用户上传照片或手绘草图，AI 先描述比例和结构、列出建模计划，再动手。
- `deepseek-flash` 本身支持图片输入，所以不用第二个模型。每张图最多约 1024 token，成本可以忽略。
- 待 spike 验证：DeepSeek 是否接受**工具结果里**的图片。不接受的话，退回到把图片作为一条用户消息附上。

## 工具清单（v1，约 16 个）

| 组 | 工具 | 说明 |
| --- | --- | --- |
| 参数 | `set_params` | 新建或修改命名参数，值可以是表达式 |
| 草图 | `sketch` | 平面可以是基准面、偏移面或某个面（选择器）。图元有矩形、圆、多边形、长圆孔、多段线（可带圆弧）。尺寸都可以用参数 |
| 实体特征 | `extrude`、`revolve`、`sweep`、`loft` | `extrude` 支持定距、对称、贯穿、到面，增料或切除，带拔模角 |
| 修饰特征 | `fillet`、`chamfer`、`shell`、`hole` | `hole` 有简单孔、沉头孔、埋头孔 |
| 复制 | `pattern_linear`、`pattern_circular`、`mirror` | |
| 编辑 | `edit_feature`、`delete_feature`、`move_feature` | 删除或移动前先报告哪些下游特征会受影响 |
| 查询 | `inspect` | 返回特征树摘要、包围盒、体积和质心，或某个选择器选中的面和边 |
| 视觉 | `look` | 渲染指定视图，可以高亮特征 |

系统提示里写明：

- **坐标约定**：Z 朝上、毫米、原点在底面中心。
- **建模原则**：草图挂在基准面上，关键尺寸做成参数，圆角放最后，抽壳前先想清楚圆角。
- **课程目录**：AI 解释某一步时，可以链接到对应的课，例如 `/lesson/fillet-shell-order`。

## 界面：`/studio`

- **布局**：左边对话（约 380 px），中间 3D 视口，右边特征树和参数面板。特征树和参数面板复用拆解页的组件。
- **对话里的工具卡片**：每次工具调用显示成一张卡片，如「拉伸1 · 30 mm ✓」「圆角1 失败：半径大于相邻边长」。点卡片，视口就回滚到那一步。
- **撤销**：按 AI 回合整体撤销，一次撤掉 AI 一个回合做的所有特征。
- **导出**：STEP、STL、build123d 代码。
- **两种模式**：
  - 「直接做」：AI 做完再讲。
  - 「边做边学」：AI 每一步先说意图；遇到圆角、抽壳这类关键步骤，先让学习者预测，再执行。这是 v2。
- **入口**：首页和导航加「AI 工作台」；拆解页加「在工作台里改这个零件」（v2，需要先把模型移植成特征树 JSON）。

## 服务端

- `server/`：Hono + AI SDK 7。`POST /api/chat` 里：
  - 模型：`streamText({ model: deepseek("deepseek-flash"), system, messages, tools })`；
  - 单次请求的步数用 `stopWhen` 限制，客户端另外限制每轮最多 20 次工具调用。
- **部署**：
  - PM2 进程 `featuretree-api`，监听 `127.0.0.1:18914`。
  - Caddy 在现有的 featuretree 块里加 `handle /api/*` 反代。
  - 密钥放在 `/root/featuretree/shared/.env`，不进仓库。
  - CI 用 esbuild 打成单文件，和静态站一样 rsync 上去后重启；健康检查走 `/api/health`。
- **访问与成本控制**：
  - 按 IP 限流，例如每小时 20 条消息。
  - 全站每日预算上限，例如每天 ¥20。用 `onFinish` 里的 usage 记账，超了就暂停，并提示用户可以填自己的 key。
  - 可选「自带 key」：存在用户浏览器本地，按请求带上，服务器不保存。
- **模型可替换**：通过环境变量切换到任何 OpenAI 兼容的服务商，自部署的人也能用。
- **隐私**：默认不记录对话内容；页面上写清楚对话会发给 DeepSeek。

## 评测

- `evals/` 放 30 个提示词，从简单方块、带孔支架、马克杯、带螺丝柱的外壳到齿轮。每个都带检查项：能重建成功、包围盒误差在 ±5% 以内、必需的特征都在、关键尺寸是参数。
- 在 Node 里无头运行：同一个解释器，工具在评测模式下直接 `execute`。报告通过率、步数、token 和成本。
- 改系统提示或工具定义时必须跑评测，通过率不能下降。评测要花钱，所以手动触发，不放进每次 CI。

| 2 · 视觉与教学 | `look` 自检、参考图输入、「边做边学」模式、草图约束（复用 planegcs）、把拆解模型移植成特征树并能在工作台里打开、分享链接 | 2–3 周 | 带图的提示词通过率 ≥ 70% |

阶段 0 结束时做一次决定（go / no-go）。要验证的是：

- 10 个提示词里至少 8 个能在 10 次工具调用以内做出正确模型。
- 思考模式和非思考模式下，工具调用分别稳不稳。
- 工具结果里能不能带图片。
- replicad 1.2 在 Worker 里的内存表现如何。
- 每一步的延迟（不含内核计算）中位数 ≤ 3 秒。

## 风险

| 风险 | 应对 |
| --- | --- |
| 大模型的空间推理弱，方向和位置容易错 | 选择器按特征相对引用；`inspect` 返回包围盒；`look` 看图自检；系统提示里写死坐标约定 |
| 内核失败 | 返回结构化错误和修法建议；界面上当讲解机会 |
| 选择器有歧义 | `expect` 数量校验，不符就列出候选报错 |
| 思考模式下的工具调用：多轮时可能要把 reasoning 回传 | spike 里验证 `@ai-sdk/deepseek` 的处理；不行就规划用思考、执行用非思考 |
| 滥用和成本 | 限流、每日预算、自带 key |
| wasm 体积和内存 | 只在 `/studio` 加载；桌面为主；内存超阈值回收 Worker |
