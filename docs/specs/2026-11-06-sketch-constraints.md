## 为什么

- **参数化建模的核心是「几何关系 + 驱动尺寸」。**
  - 工作台现在的草图只有 rect、circle、polygon、slot、polyline、text，每个图形填几个数。
  - 学习者碰不到自由度、欠定义和过定义，也碰不到「尺寸从哪里标起」这个设计意图。
- **课里学的东西在工作台用不上。**
  - 课程已经用 FreeCAD 的求解器 planegcs 讲了自由度、冗余和冲突，但只有一个固定的四边形和一排按钮。
  - 学习者到了工作台，没法在自己的零件上再做一遍。
- **对齐专业软件的习惯**，学了能直接迁移：
  - 颜色：SolidWorks 蓝色表示欠定义，黑色表示完全定义，红色表示过定义；Onshape 也用蓝色和黑色。
  - 特征树：SolidWorks 在草图名前加「(-)」表示欠定义，加「(+)」表示过定义。
  - 「智能尺寸」：点一条线标长度，点两个元素标距离或角度。
  - 「添加几何关系」：只列出对当前选择有效的关系。
- **现有的图形其实就是完全定义的草图。**
  - 比如 `rect` 的 `w`、`h` 是两个驱动尺寸，水平、竖直和居中是隐含的几何关系。
  - 编辑器把这一点显示出来，本身就是一课。

## 待讨论

1. **带约束的草图存在哪里？**
   - A. 在 `sketch` 特征上加 `geometry` 和 `constraints`，与 `shapes` 并存。一个草图里可以既有矩形，又有一条自由轮廓。
   - B. 新增一个 op，叫 `sketch2`。
   - C. 新增一种图形类型 `profile`，放进 `shapes`。
   - **建议 A。**
     - 拉伸、旋转、放样都按草图 id 引用，一处都不用改。
     - 图形和约束几何最后都变成同一个 Drawing。
     - 编辑卡片、代码导出、参数用处都只多一个分支。
     - B 会让每个用到草图的地方都要认两种 op。
     - C 把一个多环轮廓塞进 `shapes` 的一项，它的自动嵌套成孔会和 `cut` 的语义打架。
2. **助教写不写约束？**
   - A. 默认仍然用 `shapes`。只在学习者要求约束，或者图形表达不了时（L 形截面、带相切圆弧的轮廓），才写 `geometry`，而且用紧凑写法（见下文「数据结构」）。
   - B. 草图一律写成 `geometry` 加 `constraints`。
   - C. 助教不写，只给学习者手画。
   - **建议 A。**
     - 一个矩形用 `shapes` 是 1 项，展开成几何和约束要约 15 项。
     - flash 模型连选择器的 `expect` 都常错一次，写长的 id 引用错得更多。
     - C 浪费了「助教示范一个完全定义的草图，学习者再改」这条最好的教学路径。
3. **第一期做多少？**
   - A. 图元：直线、圆、三点圆弧、构造线。几何关系 8 种：重合、水平、竖直、平行、垂直、相切、相等、对称。尺寸 4 种：距离、角度、半径、直径。拖动，颜色，自由度。不引用已有的边。
   - B. 在 A 的基础上，加上引用和投影已有的边（转换实体引用）。
   - C. 只做直线。
   - **建议 A。**
     - 这已经覆盖课程里所有概念和大部分常见截面。
     - 引用已有的边要处理面和边改名的问题（拓扑命名），工作量和风险都高一档，放到第三期。
4. **在哪里求解？**
   - A. 两边都解，用同一个纯函数模块：
     - 编辑时在主线程解。拖动要 60 帧，而 Worker 可能正在重建刻字，一卡就是 1 秒。
     - 重建时 Worker 再解一次，参数面板改了尺寸也会重解。
   - B. 只在 Worker 里解。
   - C. 只在主线程解，把解出的坐标写进树。
   - **建议 A。**
     - B 拖动会跟着重建排队。
     - C 让 Node 里的评测和单元测试依赖界面，而且参数面板改数以后没人重解。
5. **在编辑器里打开一个用 `shapes` 画的草图会怎样？**
   - A. 按它隐含的约束显示：线是黑色的，尺寸标在图上。改尺寸就是改 `w`、`h`、`d`。另给一个「转成自由草图」按钮，把它展开成 `geometry`，展开后才能拖点、加关系。
   - B. 一打开就自动转换。
   - **建议 A。**
     - 不动助教写的结构，代码导出也保持简洁。
     - 学习者先看到「矩形 = 4 条线 + 水平竖直 + 两个尺寸」，再决定要不要拆开。
6. **要不要做「自动完全定义」？**
   - 它的做法是：按当前形状推断水平和竖直，给每条边、每个半径标上当前数值，再从原点标位置尺寸。
   - A. 第二期做。
   - B. 不做。
   - **建议 A。**
     - 对助教是兜底：坐标画准了，一键就能变成完全定义。
     - 对学习者是一份可以对照的答案。
     - 自动标出来的尺寸常常不符合设计意图，这一点正好可以拿来讲。

## 已定的建议

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 颜色 | 蓝色是欠定义，黑色是完全定义，红色是冲突的约束，黄色是多余的约束 | 和课程里的图例、SolidWorks 一致 |
| 自由度显示在哪里 | 编辑器顶部写「还差 N 个约束」「完全定义」或「过定义」；特征树的草图行前加「(-)」或「(+)」；悬停详情里写自由度 | 和 SolidWorks 的特征树一样，一眼看出哪个草图没定死 |
| 欠定义能不能拉伸 | 能，照常建；助教看到 `(-)` 会提醒 | 和专业软件一样；学习过程中欠定义是常态 |
| 过定义 | 冲突时，这一步报错，后面的特征跳过（和其他特征失败一样），并列出冲突的约束；多余但不冲突时只给警告，照常建 | planegcs 能分清冲突和冗余 |
| 尺寸的值 | 用 `Num`，可以写数字、参数名或表达式；编辑器里有「设为参数」，一键新建参数并写上说明（`paramNotes`） | 参数面板的「用在」会自动列出这些尺寸 |
| 拖动 | 用课程里已有的做法：给被拖的点加两个临时坐标约束，真约束优先，所以完全定义的草图拖不动 | 「定死了」能直接摸到 |
| 树里存的坐标 | 每个点存上次解出的位置，作为下次求解的初值；在编辑器里点「应用」时写回 | 初值决定解落在哪一支（例如圆弧往哪边鼓），必须存下来 |
| 导出 build123d | 导出按当前参数解出的坐标，并加注释说明 | build123d 没有草图求解器；把约束翻译成表达式只在少数情况下可行，而且容易出错 |
| 手机 | 草图编辑只在桌面上开放，手机上只能看 | 拾取线和点需要鼠标的精度 |

## 数据结构

### 例子：L 形截面

```json
{
  "id": "sk1", "op": "sketch", "on": { "plane": "XZ" },
  "geometry": [
    { "type": "polyline", "id": "p", "points": [[0,0],[60,0],[60,8],[8,8],[8,40],[0,40]], "closed": true },
    { "type": "circle", "id": "c", "center": [34, 4], "d": 4 }
  ],
  "constraints": [
    { "type": "coincident", "of": ["p.1", "origin"] },
    { "type": "horizontal", "of": ["p.l1", "p.l3", "p.l5"] },
    { "type": "vertical", "of": ["p.l2", "p.l4", "p.l6"] },
    { "type": "distance", "of": ["p.l1"], "value": "W" },
    { "type": "distance", "of": ["p.l6"], "value": "H" },
    { "type": "distance", "of": ["p.l2"], "value": "t" },
    { "type": "equal", "of": ["p.l2", "p.l5"] },
    { "type": "diameter", "of": ["c"], "value": 4 },
    { "type": "distance", "of": ["c", "p.1"], "dir": "x", "value": "W/2 + 4" },
    { "type": "distance", "of": ["c", "p.l1"], "value": 4 }
  ]
}
```

### 图元

- **基本图元**：`point { id, at }`，`line { id, from, to }`，`arc { id, from, via, to }`（三点弧），`circle { id, center, d }`。
  - 端点可以是一个点的 id，也可以是坐标；写坐标时自动生成一个点。
- **紧凑写法 `polyline`**：自动生成点 `p.1`、`p.2`…和边 `p.l1`、`p.l2`…，其中 `p.li` 从 `p.i` 连到 `p.(i+1)`，相邻的边共用端点。
  - 这样 id 可以推出来，助教不用一个个起名。
- **构造线**：图元加 `construction: true`。它不参与生成轮廓，用来画对称轴、旋转轴。
- **保留名**：`origin`、`x_axis`、`y_axis`，可以直接拿来加约束。

### 约束

- 写法是 `{ type, of: [...], value?, dir?, id? }`。
- `of` 里给多个对象时，按类型展开成多条，比如「这 3 条线都水平」。
- `id` 可以不写。不写时按顺序编号，报错和界面上就用「水平（p.l1）」这样的说法指认。

### 怎么映射到 planegcs

| 约束 | planegcs |
| --- | --- |
| 重合 | `p2p_coincident` |
| 水平、竖直 | `horizontal_l` / `vertical_l`；作用在两个点上时用 `_pp` |
| 平行 | `parallel` |
| 垂直 | `perpendicular_ll` |
| 相切 | `tangent_la`、`tangent_cc` 等，按两边的类型选 |
| 相等 | `equal_length`、`equal_radius_*` |
| 对称 | `p2p_symmetric_ppl` |
| 距离 | 点到点用 `p2p_distance`，点到线用 `p2l_distance`；带 `dir` 的水平或竖直距离用 `difference` |
| 角度 | `l2l_angle_ll` |
| 半径、直径 | `circle_radius`、`arc_radius`、`circle_diameter` |

- 尺寸的值：先用参数作用域算出表达式的结果，再作为固定的 sketch param 推给 planegcs。探针验证过，约束里引用参数名可以直接解出来。

## 求解与轮廓

- **新模块 `studio/sketch-solve.ts`**：纯函数，不依赖 DOM 和 replicad。
  - 输入：几何、约束、参数作用域、可选的拖动目标。
  - 输出：解出的点；总自由度；哪些点还能动；状态（ok / redundant / conflict）；冲突的约束和多余的约束。
  - 主线程、Worker、Node 共用这一个模块。planegcs 用到时才加载。
- **哪些点还能动**：planegcs 只给总自由度。所以对每个点在 x、y 方向各加一次临时位移，看它动不动。
  - 矩形只约束了宽时，8 次探测用了 7 ms，正确找出 `p3.y` 和 `p4.y` 还能动。
  - 只在约束变化时算，拖动的每一帧不算。
- **生成轮廓**（在内核里）：
  1. 按共用的点 id 和重合约束，把点并成组，连成边的图。
  2. 每个点正好接两条边，就是一个闭合环。环转成 replicad 的 Blueprint：直线用 `lineTo`，圆弧用 `threePointsArcTo`；整圆用 `drawCircle`。
  3. 出错的情况：
     - 只接一条边的点：报「草图没有闭合：p.3 只连着一条线」。
     - 接三条以上的点：第一期不支持分叉，直接报错。
     - 环和自己相交：报错。
  4. 嵌套：按包含关系，奇数层的环成为孔，和 SolidWorks 一样。结果再和 `shapes` 的 Drawing 合并，走现有的 `sketchDrawing`。
- **特征结果里加 `dof` 和 `status`**，特征树和助教读到的特征树都显示 `(-)` 或 `(+)`。
- **画面需要草图平面的坐标系**：内核在草图这一步的显示数据里返回 `ResolvedPlane`（原点、x、y、法向），编辑器靠它把 2D 坐标摆到 3D 里。

## 编辑器

- **入口**：
  - 编辑卡片里，草图特征多一个「编辑草图」按钮。
  - 新建草图依赖「手动新建特征」那份方案：选基准面或平面后，直接进入草图模式。
- **进入草图模式**：
  - 相机转成正对草图平面，切换为正交投影。
  - 实体半透明，后面的特征暂时回滚到这一步，和眼睛按钮的回滚一样。
- **工具条**（视图上方）：
  - 直线：连续点击画折线，点回起点就闭合，Esc 结束。
  - 矩形：4 条线，自动加上水平和竖直。
  - 圆；三点圆弧；构造线开关；尺寸。
  - 「应用」和「放弃」。
- **画的时候自动加关系**，第一期只做三种，并在光标旁显示小图标（SolidWorks 叫推理线）：
  - 接近水平或竖直时，加水平或竖直；
  - 落在已有的点上时，加重合；
  - 落在原点上时，加重合原点。
- **加几何关系**：
  - 单击选图元，Shift 多选。
  - 旁边浮出「添加几何关系」，只列出对当前选择有效的关系。例如：两条线可以平行、垂直、相等；线和圆弧可以相切；两个点可以重合、水平、竖直；两个点加一条线可以对称。
  - 已有的关系在图元旁显示小图标，单击图标可以删除。
- **尺寸**：
  - 点一个图元：线标长度，圆标直径，弧标半径。
  - 点两个：两点之间、点和线之间标距离，两条线之间标角度。距离是水平、竖直还是斜向，看鼠标把标注拖到哪里。
  - 放下标注后弹出输入框，可以填数字或表达式，有「设为参数」。双击已有的尺寸可以修改。
  - 标注线和标签沿用测量功能那一套（CSS2D 标签加线）。
- **拖动**：欠定义的点和线可以拖，图形实时跟着求解；完全定义的拖不动。
- **状态**：
  - 颜色按「已定的建议」那张表。
  - 过定义时不拦着学习者，冲突的约束标红，并建议删掉最后加的那条（课程里也这样讲）。
  - 这时「应用」照样可以点，这一步会报错。
- **撤销**：编辑器里 ⌘Z 只撤销编辑器里的操作；点「应用」后，整次编辑算一步撤销。

## 可行性（已用探针验证，`app/.tmp/gcs-probe/`）

- **planegcs 1.3.0**：
  - wasm 484 KB，brotli 后 137 KB，已经随课程上线。
  - 在 Node 里加载用了 7 ms。
- **支持的东西**：
  - 约束类型约 80 种，第一期要的 12 种（8 种几何关系 + 4 种尺寸）都有。
  - 自由度：`gcs.dof()`。
  - 冲突、冗余、部分冗余，都能列出是哪几条约束。
  - 临时约束（`temporary`）可以用来实现拖动。
  - 从动尺寸（`driving: false`）留给第二期。
- **探针结果**：
  - 4 个点、4 条线的矩形：不加约束时自由度 8；加水平竖直后 4；左下角重合原点后 2；再标宽和高后 0。
  - 再加一条一致的上边尺寸：报冗余，正确指出是 `top`。
  - 加一条矛盾的上边尺寸：解不出来，冲突列表是 `[h1,h3,v2,v4,w,top]`。planegcs 给的是一整组，不只是最后加的那条。
  - 尺寸写成参数名 `"W"`，推入 W=60、H=30 后解出 60×30。
  - 一条线加一个圆弧，加相切和半径后解出，圆心落在 (50,10)。
  - 30 个矩形、约 150 个点的草图，一次求解 62 ms。
  - 单个矩形一次求解 0.05–1 ms。

## 分期

- **一期（约 10 个工作日）**：
  - 数据结构和校验，`sketch-solve.ts`，内核生成轮廓，`dof` 和 `(-)` 显示。
  - 编辑器：「待讨论」第 3 条 A 的范围，加上拖动、颜色、尺寸输入、「设为参数」。
  - 用 `shapes` 画的草图在编辑器里按隐含约束显示，可以「转成自由草图」。
  - 助教提示词加入紧凑写法，`get_sketch` 之类的读取返回自由度。
  - 代码导出，单元测试和冒烟测试，2–3 道评测。
- **二期**：
  - 自动完全定义。
  - 草图圆角、修剪、延伸、切线弧。
  - 更多几何关系：中点、同心、点在线上、共线、固定。
  - 从动尺寸，镜像草图实体。
- **三期**：引用和投影已有的边，样条，文字跟随约束定位。

## 验收

- **单元测试**（Node 里跑 planegcs）：
  - 每种约束的映射各一个用例。
  - 矩形的自由度依次是 8 → 4 → 2 → 0。
  - 能识别冗余和冲突，并给出约束名。
  - 改参数 W 后重建，尺寸跟着变。
  - 开口、分叉会报错；内环会成为孔。
  - L 形截面拉伸后的体积正确。
- **冒烟测试**：
  - 进入草图编辑器画矩形，水平和竖直自动加上。
  - 标出宽和高后，状态变成「完全定义」，线变黑，拖不动。
  - 再加一个矛盾的尺寸，冲突的约束标红。
  - 删掉它后点「应用」，拉伸结果的尺寸正确。
- **真模型评测**：
  - 新增一道：「画一个 L 形截面，用约束和尺寸，宽度用参数 W，拉伸 20」。检查自由度为 0，尺寸引用了 W，体积正确。
  - 原来的题不退步（默认仍用 `shapes`）。
- **性能**：50 个点的草图，拖动时每帧求解少于 5 ms；重建时求解少于 20 ms。

## 风险

- **助教写约束会写错**：引用错 id，或者同一个尺寸标两次导致过定义。
  - 工具结果里给出自由度和冲突的约束，让它自己改。
  - 紧凑写法让 id 可以推出来；二期的自动完全定义再兜一层底。
  - 用评测量出到底错多少。
- **求解落到另一支**：
  - 初值离解太远时，可能收敛到另一个解，比如圆弧翻到另一边、两条线交叉。
  - 参数大改时也可能翻转，FreeCAD 有同样的问题。
  - 先靠「应用时写回初值」缓解。评测或手测发现了，再加一条：重建后把解写回树，不进撤销栈。
- **冲突报的是一整组**：planegcs 的冲突列表常常包含所有相关的约束，界面必须标出整组，不能只指一条。
- **界面工作量**：草图编辑器是整个工作台最重的界面，要处理拾取、推理、标注放置和撤销。一期严格按上面的范围做，不做修剪、样条和引用。
- **后续特征选不到面**：草图改了以后，后面特征的选面条件可能对不上。这个问题现在改 `shapes` 时就有，不是新问题。
