# 工作台：在模型上标注，让修改指向具体位置

- 状态：第 1、2 步已实现（2026-11-06）。
  - 真模型评测 13/13 通过，含 3 道标注题，每道 2–3 次调用。
  - 浏览器实测：点面开孔、点棱倒圆角都一次做对。
- 日期：2026-11-06
- 范围：方案里的第 1、2 步。第 3 步（不经 AI 的快捷操作、AI 反过来请学习者点选）等前两步用一段时间再定。
- 相关：`docs/specs/2026-11-05-ai-modeling.md`（工作台总体方案）、`docs/dev/studio.md`

## 一句话

学习者在视图里点一下模型，系统就知道指的是哪个面或哪条边。发给 AI 的不是「左上角那里」，而是内核验证过、只会选中那一个的语义选择器，外加点击位置和带编号的截图。

## 为什么

- 用文字描述位置很难：「右边那个孔」「靠近把手的边」，模型常常选错面，要来回好几轮。
- 工作台的选择器本来就是语义的，改了参数也照样选得对。点选只是把「学习者指的那个」翻译成选择器，并在发出前验证它只选中一个。
- 教学上也有用：点一下就能看到这个面是哪一步做出来的。

## 已定的决定

| 问题 | 决定 | 理由 |
| --- | --- | --- |
| 标注一次性还是持久 | 一次性：随下一条消息发出，这一轮回复完就从视图里清掉；消息里留着标签，可以回看 | 持久的批注列表要管状态、管「AI 处理了没有」，先不做 |
| 怎么进入标注 | 直接单击模型；拖动仍是转视角 | 不用切模式；顺带显示「来自哪个特征」 |
| 要不要附截图 | 附一张带编号图钉的当前视图 | 模型能看到 ① 在哪；一张小图，成本很低 |
| 选什么 | 点在边附近（屏幕 8px 内、没被挡住）选边，否则选面；点击位置总会记下 | 圆角、倒角要边，打孔、凸台要面和位置 |

## 交互

1. **单击**：按下到抬起的位移小于 5px 才算点击，否则是转视角。
   - 只在看最新一步、内核就绪、AI 没在回复时可以点选。
   - 回滚到中间某一步时点模型，会提示先回到最新一步。
2. **高亮和卡片**：选中的面或边高亮，旁边浮出卡片：
   - 第一行写选中了什么：「平面 · 朝上（+Z）· 来自『拉伸1』」；
   - 第二行是事实：面积、半径、长度；
   - 输入框「这里想怎么改？」，按钮「加到消息」（Enter）和「取消」（Esc）。
3. **加到消息**：
   - 视图里留下编号图钉 ①②③，跟着视角一起转；
   - 输入框上方出现标签「① 顶面：开个 ⌀8 孔」，点它会重新高亮，× 可以删掉；
   - 可以连续标几处再一起发；不写正文、只发标注也行（正文默认「按标注修改」）。
4. **发送后**：
   - 消息气泡里显示这些标签和那张截图；
   - 视图里的图钉留到这一轮回复结束再清掉；
   - 之后点历史消息里的标签，会在当前模型上重新解析选择器并高亮；解析不到就提示「这个位置已经变了」。
5. **回复里的编号**：助教回复里出现的 ①②③ 可以点，效果同上。

## 发给模型的内容

浏览器把标注存进这条消息的 metadata（和模型状态快照一起）；服务端把它整理成一段文字，附在这条消息后面。截图作为这条消息的图片一起发出。

```
## 标注（学习者在模型上点选的位置）
[标注 ①] 学习者的备注：这里开一个 ⌀8 的通孔
- 选中：面 · 平面 · 法向 +Z · 来自特征 base（拉伸1）· 面积 2400 mm²
- 点击位置：(12, -5, 30)
- 已验证只选中它的选择器：{"of":"base","normal":"+Z","extreme":"+Z","expect":1}
- 在这个面上画草图：on = {"plane":"XY","face":<上面的选择器>}；点击处的草图坐标 (12, -5)
```

- **选择器怎么来**：内核从「来自哪个特征 + 类型 + 方向或半径」开始试，选中的不止一个就逐步加条件（最靠外、坐标、靠近点击位置），直到恰好选中目标为止，再加上 `expect: 1`。每个候选都在当前模型上实际跑过。
- **草图坐标**：法向是坐标轴方向的平面，直接给出基准面、偏移和草图坐标，省掉模型最容易算错的换算。
- **截图**：用学习者当前的视角渲染，编号画在图钉位置。`look` 渲染时也画上这一轮的图钉，模型改完可以自检。
- **提示词**：标注里的选择器已经验证过，优先直接用；新特征的位置用给出的草图坐标；回复里用 ①② 指代标注。

## 实现

| 地方 | 改动 |
| --- | --- |
| `kernel/build.ts` | 显示数据里每个面、每条边带上 hash；新增 `pick`（hash + 点 → 描述、验证过的选择器、草图坐标）和 `locate`（选择器 → 命中的 hash） |
| `kernel/select.ts` | `uniqueFaceSelector` / `uniqueEdgeSelector`：按候选逐个验证 |
| `worker.ts`、`client.ts` | 两个新请求 |
| `annotations.ts`（新） | 标注的类型、zod 校验、给模型的文字格式（服务端和评测共用） |
| `scene.ts` | 按单个面或单条边高亮 |
| `routes/studio.tsx` | 点击判定、面和边的拾取（边在屏幕空间找最近的、检查遮挡）、图钉（CSS2D）、卡片（Popover，虚拟锚点） |
| `use-studio-chat.ts`、`ui/chat-panel.tsx` | 待发标注、输入框上方的标签、发送时组装截图和 metadata、历史标签、回复里的 ① 可点 |
| `look.ts` | 截图和 `look` 都能画编号图钉，支持用学习者当前的视角 |
| `server/index.ts` | 把每条用户消息的标注整理成文字附上（只追加，不改前缀，缓存照样命中） |
| `prompt.ts` | 标注的用法 |
| 评测 | 3 道带标注的题：在指定面上打孔、给指定边倒圆角、把指定凸台加高 |

## 实现中发现并处理的

- **相切线**：圆角和相邻面之间的线画出来像边，点到它时，模型的倒圆角会失败。现在内核会判断两侧面在这条线上是否光滑过渡；是的话就改选光标下的面。
- **选中的边看不清**：边贴在面上，被面挡住了。现在用主色粗线、始终画在最上层。
- **手机上卡片被挤出屏幕**：窄屏改为放在点的下方居中。

## 风险

- **模型改完后拓扑变了**：标签靠选择器重新解析；解析不到就提示，不会指错。
- **点击和转视角冲突**：用位移阈值区分，触屏同理。
- **选错了**：卡片先说清选中了什么，发送前就能发现，取消重点即可。
- **截图费用**：每条带标注的消息多一张 448×336 的小图。

## 验收

- 单元测试：
  - 盒子、带孔板、杯子、阶梯轴上，随便挑面和边，生成的选择器都恰好选中目标；
  - 改参数后，同一个选择器仍然选中「同一个」面。
- 冒烟测试（脚本模型）：
  - 点模型出卡片、加到消息、标签出现；
  - 发送后消息里有标签，图钉在回复结束后清掉。
- 评测：3 道标注题在真模型上通过，原来 10 道不退步。
- 浏览器实测（真模型）：
  - 点顶面让它开孔，孔开在点的位置；
  - 点一条边让它倒圆角，只倒那一条。
