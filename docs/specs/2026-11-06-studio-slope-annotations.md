# 工作台：在斜面上标注时，附上斜面上的草图坐标

- 状态：已实现（2026-11-07）
- 日期：2026-11-06
- 范围：学习者在斜面上点选做标注时，发给模型的内容里带上这个斜面上的草图坐标，规则和 `on.face` 的斜面草图完全一致。边和曲面不在范围内。
- 相关：
  - `docs/specs/2026-11-06-studio-annotations.md`（标注）
  - `docs/specs/2026-11-06-studio-tools.md`（斜面草图）
  - `docs/specs/2026-11-06-studio-hand-modeling.md`（标注卡片的「在这个面上画草图」也用这个坐标）

## 已确认（2026-11-07，均按建议）

没有需要你拍板的分叉：坐标规则沿用已上线的斜面草图规则。只有一个默认值请过目：**边不给坐标**（理由见「不做」）。

## 为什么

- 现在 `Kernel.pick()`（`app/src/studio/kernel/build.ts`）只在面的法向沿坐标轴时给出 `sketch`（基准面、偏移、点击处的草图坐标）。斜面上 `axisDir` 为 null，`sketch` 就是 null。
- 结果是模型只拿到选择器和三维的点击位置，要自己把三维点换算到斜面的草图坐标：原点在面中心，x 水平，y 沿坡往上。标注方案给草图坐标，本来就是为了省掉这种模型最容易算错的换算。
- 评测里的「斜面中心立凸台」能过，是因为中心正好是 (0, 0)。点在斜面上别的位置时，现在要靠模型自己算。
- SolidWorks、Onshape 在任意平面上画草图，用的都是这个面自己的坐标系；我们的规则已经定了，这次只是把同一套坐标也交给标注。

## 规则

- **什么算斜面**：选中的是平面，法向不沿任何坐标轴。
- **坐标系**：和 `on.face` 选中斜面时一模一样（`Kernel.plane()` 的斜面分支）：
  - 原点 c = 这个面的中心；
  - x = Z × n（单位化）；n 接近 ±Z 时取 X 轴；
  - y = n × x；
  - 点击处的坐标 (u, v) = ((p − c) · x, (p − c) · y)。
- **只写一份**：把这段坐标系从 `plane()` 抽成一个函数（例如 `faceFrame(face)`），`plane()` 和 `pick()` 共用。这样给模型的坐标和草图的实际落点不会对不上。
- **顺手修一个小问题**：坡度在约 0.8°–2.6° 之间时，现在 x 直接取 X 轴，和法向不完全垂直，replicad 会再投影一次。抽函数时先把 x 正交化，误差本来就小于 0.1%。
- **`on` 怎么写**：`{ plane: "XY", face: <已验证的选择器，去掉 expect> }`。斜面不平行于任何基准面，`plane` 只是占位，不参与定位。孔的 `on` 也一样，`at` 就填这个坐标。

## 数据和文字

- `PickInfo.sketch` 和 `Annotation.sketch`（`app/src/studio/annotations.ts`）加一个可选字段 `face: { origin, x, y, normal }`。有它就表示坐标在斜面上；斜面时 `plane` 填 "XY"，`offset` 填 0。旧消息里的标注没有这个字段，照旧解析。
- `annotationText` 的斜面行：

```
- 在这个斜面上画草图：on = {"plane":"XY","face":<选择器>}；点击处的斜面草图坐标 (12.5, 4)
  （原点是这个面的中心 (0, 0, 20)，x 沿 (0, -1, 0) 水平，y 沿 (0.89, 0, 0.45) 往上，法向 (-0.45, 0, 0.89)）
```

  - 附上三维方向，模型可以自己核对；
  - 提示词的「标注」一段加半句：斜面标注给的是斜面草图坐标，直接用。
- 标注卡片不变：坐标只给模型，学习者看的仍然是「平面 · 来自『楔形』· 面积…」。

## 不做

- **边**：边不是草图平面。要在边旁边开孔，学习者点旁边的面就行；模型拿到边的选择器，也够用来做圆角、倒角。
- **曲面**（圆柱面等）：草图贴不上去，不给坐标。

## 实现

| 地方 | 改动 |

| `kernel/build.ts` | 抽出 `faceFrame`，`plane()` 和 `pick()` 共用；`pick()` 的斜面分支给出 `sketch.face` 和 (u, v) |
| `annotations.ts` | `PickInfo`、`Annotation` 的可选 `face`；`annotationText` 的斜面行 |

## 风险

- **原点跟着面走**：原点是面的中心，斜面变长时，同一个 (u, v) 会跟着平移。这和 `on.face` 的规则一致；标注是一次性的，只影响这一轮。
- **斜面的选择器常常要靠位置**：没有沿轴的法向，合成的选择器多半是「来自某特征 + 最靠外」，最差用 `near`。已有的验证保证它只选中这一个面。

## 验收

- 单元测试：
  - 楔形块（坡度约 27°）的斜面上取三个点，用 `pick` 给出的 `on` 和 (u, v) 画一个 ⌀2 的圆，拉伸切除。孔的轴线穿过点击点，误差小于 0.01 mm，且垂直于斜面；
  - 坡度 1° 的缓坡同样成立（覆盖正交化）；
  - 法向沿坐标轴的面，输出和现在一样。
- 评测 `anno-slope`：楔形块，在斜面上偏离中心的位置标注「在这里开一个 ⌀6 的孔，垂直于斜面」。通过条件：孔心在点击处 1 mm 以内，轴线垂直于斜面。原有 17 道不退步。
- 浏览器实测：在「斜面中心立凸台」的结果上点斜面靠上的位置，让助教在那里打孔，一次做对。
