# 工作台：需求核对表

- 状态：已实现（2026-11-07）
- 日期：2026-11-07
- 范围：AI 建完以后，把学习者提出的每个数值要求列成核对项。建模内核实际量出来，打 ✓ 或 ✗。学习者改参数以后自动重算。
- 不在范围：公差判定（按图纸公差判合格）、装配之间的干涉检查。
- 相关：`app/src/studio/kernel/measure.ts`（测量）、`app/src/studio/kernel/select.ts`（选择器）、`app/src/studio/evals.ts`（评测里的自动检查）、`app/src/studio/tools.ts`、`app/src/studio/prompt.ts`、`app/src/studio/apply.ts`

## 已确认（2026-11-07，均按建议）

1. **学习者改了参数以后，核对表怎么显示？**
   - 甲：一直显示并实时重算。如果是学习者自己改的参数让它不再满足，这一行显示成「已偏离原要求」（灰黄色，不算错）；只有助教建出来就不满足的才是红色 ✗。
   - 乙：只显示助教回复那一刻的结果，之后不变。
   - **建议甲。** 这正是核对表最有用的地方：改了参数，马上知道还满不满足原来的要求。
   - 例子：法兰盘的要求是「6 个 ⌀8 孔均布在 ⌀90 圆上」，你把 pcd 拖到 100，这一行变成「⌀90 → 现在 ⌀100（你改过 pcd）」，不是一个刺眼的红叉。
2. **核对表放在哪？**
   - 甲：对话里出一张卡片，记的是那一刻的结果；同时「参数」页最上面放一份实时的「要求核对 5/5」，展开就是同样的表。
   - 乙：只在对话里。
   - **建议甲。** 对话会往上滚走，而改参数就在「参数」页；在同一页看到「改了 → 还满足吗」最顺手。
   - 例子：在「参数」页把壁厚 t 从 2 改成 1.5，上面的「壁厚 2」一行立刻变成「已偏离：现在 1.5」。

## 为什么

- 方向是「AI 建，人看懂，人改」。人最想知道的第一件事是：它建得对不对？现在只能自己点测量一个个量，或者相信助教的总结。
- 助教偶尔会把要求读错、算错，比如把「孔心离边 8」做成离中心 8。评测里有自动检查才发现得了，学习者没有。核对表把评测的那套检查交给学习者，而且人只需要看，不需要操作。
- 核对项由内核量，不是由模型「自己说」：数值来自 OpenCascade 的实际几何。助教说「已完成」和内核量出来「✓」是两回事。
- 核对项跟着特征树保存。分享出去，对方也能看到「这个零件满足哪些要求」（见 `2026-11-07-studio-share.md`）。

## 已定的建议

| 问题 | 建议 | 理由 |
| --- | --- | --- |
| 谁列要求 | 助教从学习者的话里列，每项带一句「你说的：……」原话 | 学习者看原话就能发现助教读错了 |
| 存在哪 | 特征树上加 `checks`（可选），和参数、特征一起保存、撤销、分享 | 要求是零件的一部分；改参数后能重算 |
| 期望值写什么 | 只能写学习者给的数字，不能写参数名 | 写成参数名就永远 ✓，失去意义 |
| 什么时候核对 | 学习者的话里有具体数值时，建模轮次结束前必须调用一次；没有数值的轮次不用 | 不给每轮都加开销 |
| 容差 | 长度 ±0.01 mm，角度 ±0.05°，体积 ±0.5%；某项可以单独放宽 | 参数化建模得到的几何是精确的，差了就是做错了 |
| 学习者能不能改核对项 | 一期不能，只能看；不对就对助教说 | 操作越少越好 |
| 何时重算 | 每次重建后自动重算（核对放在重建报告里） | 改参数、撤销、回滚都不用额外操作 |
| 回滚到中间某一步时 | 核对表变灰，写「回滚中，按最新一步核对」 | 中间步骤本来就不满足最终要求 |

## 核对项的种类

助教用现有的语义选择器指明「量哪里」，内核负责量。

| 种类 | 例子 | 内核怎么量 |
| --- | --- | --- |
| `size` 外形 | 「80×50×30，长沿 X」 | 包围盒三个方向的尺寸；`axes: "any"` 时排序后比较，同评测的「尺寸」检查 |
| `thickness` 壁厚 | 「壁厚 2」 | 选中的平面：和它反向、投影有重叠的平面之间的最短距离（`BRepExtrema`）；圆柱面：和它同轴的另一圆柱面的半径差 |
| `holes` 孔 | 「4 个 M4 螺纹孔」「6 个 ⌀8 通孔」 | 选中的圆柱面按轴线归成孔，数个数、量直径；写了螺纹规格时，再对照孔特征的 `standard` 和装饰螺纹 |
| `distance` 距离 | 「孔心离两条边各 8」 | 复用 `measure.ts` 的关系：平行面间距、圆心到平面、轴线间距、最短距离 |
| `pcd` 节圆 | 「均布在 ⌀90 圆周上」 | 各孔轴线到阵列轴的距离都等于期望的一半，个数对，间隔角相等 |
| `angle` 角度 | 「斜面 30°」 | 两面夹角，复用 `measure.ts` |
| `volume` 体积（可选） | 「体积不超过 50 cm³」 | 实体体积，可以写上限、下限 |

- 每项最多量 50 个面或边，超了这一项报「量的范围太大，缩小选择器」。
- 选择器选不到东西时，这一项显示「没找到要量的东西」，算 ✗。这往往说明模型缺了这个结构。

## 新工具 `check`

```ts
check: tool({
  description: "核对学习者提出的数值要求：每项由内核实际量出来，返回 ✓ / ✗。学习者的话里有具体数值时，建模结束前必须调用一次。",
  inputSchema: z.object({
    items: z.array(z.object({
      id: z.string().describe("短英文 id，如 size、wall、holes；同 id 会覆盖原来那一项"),
      said: z.string().describe("学习者的原话片段，如「壁厚 2」"),
      kind: z.enum(["size", "thickness", "holes", "distance", "pcd", "angle", "volume"]),
      // 各种类自己的字段（真正实现时用按 kind 区分的联合类型）：
      // size:      expect [x, y, z], axes?: "xyz" | "any"
      // thickness: faces: FaceSelector, expect
      // holes:     faces: FaceSelector, count, d?, thread?: "M4"
      // distance:  a, b: FaceSelector | EdgeSelector, expect
      // pcd:       faces: FaceSelector, count, expect（直径）, axis?: "Z"
      // angle:     a, b: FaceSelector, expect
      // volume:    min?, max?
      tol: z.number().optional(),
    })).max(20),
    remove: z.array(z.string()).optional().describe("学习者不再要求的项"),
  }),
})
```

- **返回给模型的文字**，每项一行：

  ```
  ✓ size「80×50×30」：实际 80 × 50 × 30
  ✗ holes「孔心离边 8」：实际离边 12（孔在 (28, 13)）
  ```

- **提示词**加一段：
  - 建模结束前调用 `check`，每个数值要求一项，期望值写学习者给的数字；
  - ✗ 时先用 `edit_feature` 修模型，再核对一次；修不了的在回复里直说哪项不满足、为什么；
  - 不要为了让 ✗ 变 ✓ 去改期望值，除非学习者改了要求。
- **执行**：浏览器执行，和 `inspect` 一样。核对项合并进 `tree.checks`，重建后由内核算出结果。

## 界面

- **对话里的卡片**：工具卡片显示成一张小表，每行「你说的 → 实际 → ✓ / ✗」。卡片顶部写「核对 4/5」。卡片记的是那一刻的结果。
- **「参数」页顶部**：「要求核对 5/5 ✓」，可以展开，内容实时。全部通过时收起成一行，有 ✗ 或偏离时自动展开。
- **指向一行**：模型上高亮这一项量的面或边，`distance`、`thickness` 再画出量的那段线，复用测量功能的尺寸线。
- **✗ 的行**：点「让助教修正」，输入框里预填一句话，例如「核对没通过：孔心离边应为 8，现在是 12，请修正。」，学习者可以改了再发。
- **状态颜色**：✓ 成功色；✗ 危险色；「已偏离原要求」用 warning 色。颜色之外都配图标和文字，颜色不是唯一的信号。

## 分期

- **一期（本方案，约 3–4 天）**：
  - `check` 工具，七种核对项（壁厚只做平面和同轴圆柱面）；
  - 对话卡片，「参数」页的实时核对表；
  - 指向高亮，「让助教修正」；
  - 提示词，评测统计。
- **二期**：
  - 学习者自己加、删核对项；
  - 导出代码时带 `assert`；
  - 工程图的标题栏旁列出「满足的要求」。

## 验收

- **单元测试**：
  - 七种核对项各有通过和不通过的例子：盒子的外形和壁厚、四角孔离边、法兰的节圆、斜面角度、杯子的壁厚（同轴圆柱面）；
  - 改参数后重算：法兰改 pcd，`pcd` 项从 ✓ 变成偏离；
  - 选择器选不到东西时报「没找到要量的东西」；
  - `check` 的合并、覆盖、`remove`。
- **评测**：17 道题都要求助教调用 `check`，量出这几项：
  - **覆盖率**：题面里的数值要求，有多少列成了核对项。每道题先人工数一遍，写进 `EvalCase`。
  - **一致率**：助教的核对结果和评测自动检查的结果，是否一致。
  - **多抓到的错**：先 ✗、修好后 ✓ 的次数，也就是没有核对表时会交出去的错。
  - **代价**：每题多几次工具调用、多花多少钱和时间，目标不超过 15%。
  - 另加 2 道容易做错的题，例如「孔心离两条边各 8」和「壁厚从外面量是 3」，看核对表能不能抓住。
- **冒烟测试**（mock 模型）：带 `check` 的回复显示卡片；「参数」页显示「要求核对」；改参数后那一行变成「已偏离」；指向一行时视图有高亮。
- **浏览器实测**：「做一个 80×50×30 的盒子，壁厚 2，四角 M4 螺纹孔」，核对表 4 项全部 ✓；把 t 改成 1.5，「壁厚」一行变成偏离。

## 风险

- **助教把要求读错**：比如核对项本身就写成离中心 8，表上全 ✓ 但做错了。每项都带学习者的原话，人一眼能对出来；评测的覆盖率和一致率也会暴露。
- **助教为了通过改期望值**：提示词禁止这样做；评测里把「同一 id 的期望值被改过」记一笔。
- **选择器量错了地方**：指向一行就高亮量的位置，量错了一眼能看到。
- **开销**：每次重建都要算一遍核对项。刻字这种面很多的模型上，壁厚这种项会慢。每项限 50 个面或边，超过 200 ms 的项在报告里记下来，以后再优化。
- **偏离和错误分不清**：靠「谁改的参数」区分。撤销、导入、复制分享的模型时，偏离标记清空，按原值重新判断。
