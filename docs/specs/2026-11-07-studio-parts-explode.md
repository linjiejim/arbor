# 工作台：拆件、爆炸视图、分件导出

- 状态：已确认，待实施（2026-11-07，待确认的各条均按建议）
- 日期：2026-11-07
- 范围：
  1. 把一个实体按一个平面切成几个有名字的零件，例如底壳和上盖；
  2. 拆开以后，后面的特征可以只改其中一个零件；
  3. 零件分色显示，视图里加「爆炸」滑块；
  4. 分件导出：一个 STEP 文件里放多个零件；每个零件一个 STL，打包成 zip；3MF 可选。
- 不在范围：装配约束（配合）、零件之间的运动、装配图、BOM。
- 相关：
  - 拆解页的爆炸图：`app/src/three/teardown-scene.ts`（`BakedAssemblyScene`）、`app/src/three/baked.ts`、`app/src/routes/teardown.tsx`
  - `docs/specs/2026-11-06-studio-tools.md`（剖视、测量）
  - `docs/specs/2026-11-07-studio-dimensions.md`（尺寸）、`docs/specs/2026-11-06-studio-drawings.md`（每个零件一张图）

## 为什么

- **外壳要分成两半才装得进东西。** 拆解页的「桌面温湿度计」就是底壳加上盖。现在助教只能建一个整体的壳：打印出来是封死的，电路板放不进去。
- **零件太大，打印机放不下。** 一根 300 mm 长的杆，打印机最长只能打 220 mm，得从中间切成两段，分别打印。
- **带盖的盒子。** 盒体和盖子先作为一个整体建，外形和孔位天然对齐；拆开后，再只在盖子上开按键孔，只在盒体侧面开 USB 口。
- **看懂零件怎么装在一起。** 拆解页靠爆炸图讲装配关系。学习者自己做的东西拆成几件后，也应该能炸开看。
- **交付。** 每个零件要单独导出、单独打印，以后还要单独出图。

现在的工作台始终只有一个实体：出现多块不相连的料时，`kernel/build.ts` 只给一个警告「现在是 N 个不相连的实体」，没有「零件」这个概念。

## 已确认（2026-11-07，均按建议）

1. **一期只做「先建整体再拆开」，还是也让助教直接建好几个零件？**
   - 甲：一期只做拆件。先建成一个整体，再一刀切开。例子：先建好封闭的盒子，然后说「在离底 20 mm 处拆成底壳和上盖」。
   - 乙：一期就让助教直接建多个零件。例子：「做一个盒子，再另外做一块盖板放在它上面」。
   - **建议甲。** 外壳、超长件这些最常见的情况都是先整体后拆开，外形和孔位自然对得上。零件名、`part` 字段这套结构一期就会做好，乙到二期只需要放开「加料时新建一个零件」。
2. **零件用什么颜色区分？**
   - 甲：几种深浅不同的灰。表示「这一步新加了哪些面、改了哪些面」的蓝色和橙色照旧叠在上面。
   - 乙：每个零件一种彩色，比如上盖蓝、底壳绿。
   - **建议甲。** 工作台里蓝和橙已经有固定的意思，彩色零件会和它混在一起。拆解页的零件也是用深浅区分的（`model`、`modelDark`、`metal`）。
3. **止口放到第二期？**
   - 止口是上盖内侧往下伸出的一圈唇边，插进底壳里起定位作用，另外还要留一点配合间隙。
   - **建议放二期。** 一期的平切已经能打印，也能用螺丝装起来。止口需要台阶形的分界面和间隙参数：探针已经验证能切出来（110 ms，体积守恒），但参数和提示词要单独设计，也要单独评测。

## 两种做法

**(a) 新特征 `split`：建好整体以后，用一个平面把它切开。**

- 切面可以是基准面加偏移、选中的一个平面，也可以是倾斜的平面。写法和草图平面相同，复用 `PlaneRef`。
- 切开的两侧各起一个名字。
- 优点：外形和孔位天然对齐，助教只需要多写一步。
- 不足：只能平切。台阶形的分界面要靠二期的止口。

**(b) 助教直接建多个零件：特征带上 `part`，写一个新名字就是一个新零件。**

- 优点：更自由，盖子可以和盒体完全不同。
- 不足：两个零件之间的对齐要靠助教自己算尺寸，出错的机会更多，评测也更难写。

两种做法用的是同一套数据结构：每一步存一张「零件名 → 实体」的表，特征可以带一个 `part`。一期先做 (a)，(b) 在二期只是放开「加料时新建零件」。

**零件靠名字保持身份。** 每一步都存「零件名 → 实体」，后面的特征改的是某个名字对应的实体，不用在每次重建后再去猜哪块是哪块。所以在拆件之前改总高、改壁厚，整棵树重建以后，「上盖」还是上盖，后面写着 `part: "上盖"` 的特征照样作用在它上面。

## 已定的建议

| 问题 | 建议 | 理由 |
| --- | --- | --- |
| 零件怎么存 | 内核的每一步存一张有序的「零件名 → 实体」表。拆件之前只有一个没有名字的零件，界面和助教都看不到零件这一层。显示、统计、旧的 `body` 用这张表拼成的整体 | 没拆过的模型和现在完全一样 |
| `split` 的字段 | `by: PlaneRef`（基准面、偏移、`face`、`tilt` 都能用）；`parts: [背面一侧的名字, 法向一侧的名字]`；`of?`：已经有多个零件时，要拆哪一个 | 和草图平面同一种写法，模型已经会写。按「法向一侧」命名不用猜：XY 的法向是 +Z，所以先写下面的、后写上面的 |
| 一刀切出好几块 | 按每一块在平面的哪一侧，归到两个零件里。某个零件由几块不相连的料组成时，照旧给警告 | 例如平面同时切过四根立柱 |
| 切面没碰到实体 | 报错：「切面没有碰到实体：沿 Z 的范围是 0–30，现在切在 35」 | 改了总高以后最容易出这个错 |
| 后面的特征作用在哪个零件 | 特征可以写 `part`。不写时：<br>• 切除和孔作用在工具碰到的所有零件上；<br>• 加料作用在工具碰到的那一个零件上，碰到两个时报错，让写 `part`；<br>• 圆角、倒角把选中的边按零件分组，分别做；<br>• 抽壳、拔模有多个零件时必须写 `part`；<br>• 阵列、镜像跟着被复制的特征走 | 一个螺丝孔正好要穿过上盖和底壳；加料、抽壳不指定零件就分不清 |
| 选择器在哪个范围里选 | 写了 `part` 时，只在这个零件的面、边里选；没写时在所有零件里选。候选列表和 `inspect` 的输出都带零件名，例如「上盖 · 平面 · 法向 +Z」 | 「最上面的面」在拆开以后指的是上盖的顶面，前缀让助教和学习者都能看出它属于哪个零件 |
| 面的来历 | 每个零件分别比对前后两步的面。切开时新出现的切面，来历记为 `split` 这一步 | 用 `of: "sp"` 就能选中分界面上的边，例如给分模线倒角 |
| 摘要 | 写清作用到了哪几个零件，例如「切除 · 上盖、底壳」「拆成 底壳（V=16859）、上盖（V=4937）」 | 默认规则猜错时，学习者和助教都能一眼看出来 |
| 颜色 | 零件按顺序用 `--scene-part-1…4` 四种深浅不同的灰，亮色和暗色模式各一套，写在 `featuretree-theme.css` 里。「新增 = 蓝、修改 = 橙」叠在上面 | 见待确认第 2 条 |
| 特征树 | 有零件时，顶部多一行「零件」，列出每个零件的色块、名字和眼睛按钮（隐藏或显示）；指向一行时高亮这个零件。写了 `part` 的特征，名字后面加一个灰色小标签「上盖」 | 藏起上盖就能看见底壳里面；`part` 一眼就看得到 |
| 爆炸 | 视图右侧工具栏在测量、剖视下面加「爆炸」按钮，零件少于 2 个时置灰。点开是一个滑块面板（0–100%），样式同剖视面板 | 和拆解页的爆炸滑块一样 |
| 爆炸的方向和距离 | 每一刀都会让法向一侧的零件沿法向移动 d，d 取整体沿法向尺寸的 0.6 倍，至少 15 mm。一个零件的位移是它在法向一侧的那几刀的位移之和。所以底壳不动，上盖往上抬；一根杆切两刀，三段沿杆的方向依次排开。二期助教直接建的零件没有刀，就从整体中心指向零件中心 | 和拆解页一样：位移 = 向量 × 滑块，下面的零件不动 |
| 和拆解页共用代码 | 把 `BakedAssemblyScene` 里的位移计算（`apply`）和取景时的包围盒扩展（`frame`）抽到 `src/three/explode.ts`，拆解页和工作台都用它 | 一套爆炸逻辑，只维护一份 |
| 爆炸时点选、测量 | 点到的位置先减去这个零件的位移，再交给内核。测量结果按装好的位置算，并注明「按装配位置」 | 分开看时量的是真实间隙 |
| 剖视 | 拆件后照常可用，可以和爆炸一起用 | 剖开看底壳和上盖的壁厚 |
| 导出 STEP | 一个文件，每个零件是一个带名字的实体，用 replicad 的 `exportSTEP([{ shape, name }])` | 探针已验证；FreeCAD、SolidWorks 打开后会看到两个零件 |
| 导出 STL | 只有一个零件时和现在一样。多个零件时导出一个 zip，每个零件一个文件，例如 `底壳.stl`、`上盖.stl` | STL 一个文件只能放一个零件；打印要分开放 |
| 导出 3MF | 一期最后做，时间紧就移到二期。一个文件，多个带名字的对象，单位 mm | Bambu Studio、PrusaSlicer 打开就是分开的几个零件 |
| zip 库 | 加 `fflate`（MIT，压缩后约 8 KB），zip 和 3MF 都用它 | 项目里现在没有 zip 库 |
| 导出 build123d | 每个零件一个变量，变量名用 `part_1`、`part_2`，旁边注释零件名。拆件写成 `split(body, bisect_by=Plane…, keep=Keep.BOTTOM)` 和 `keep=Keep.TOP` 两次。写了 `part` 的特征改对应的变量，最后输出 `Compound([part_1, part_2])` | 用 build123d 的标准写法；中文名不能直接当变量名 |
| 给助教看的 | `inspect` 的实体概况按零件列出名字、体积、包围盒；标注发给模型时带上零件名；提示词加两句：「外壳要拆开用 split」「拆开后只改一个零件就写 part」 | 助教要知道「上盖」是哪一块 |
| 参数 | 拆件高度可以写参数，例如 `Hs`，参数面板的「用在」里会显示「拆件 · 位置」 | 改高度，分界面就跟着走 |

## 例子

封闭的盒子，在离底 20 mm 处拆开，然后只在上盖开一个按键孔：

```json
{ "params": { "L": 80, "W": 50, "H": 30, "t": 2, "Hs": 20 },
  "features": [
    { "id": "sk", "op": "sketch", "on": { "plane": "XY" }, "shapes": [{ "type": "rect", "w": "L", "h": "W" }] },
    { "id": "box", "op": "extrude", "sketch": "sk", "distance": "H" },
    { "id": "sk2", "op": "sketch", "on": { "plane": "XY", "offset": "t" }, "shapes": [{ "type": "rect", "w": "L-2*t", "h": "W-2*t" }] },
    { "id": "cav", "op": "extrude", "sketch": "sk2", "distance": "H-2*t", "mode": "cut", "name": "内腔" },
    { "id": "sp", "op": "split", "name": "拆成底壳和上盖", "by": { "plane": "XY", "offset": "Hs" }, "parts": ["底壳", "上盖"] },
    { "id": "btn", "op": "hole", "part": "上盖", "on": { "plane": "XY", "face": { "normal": "+Z", "extreme": "+Z" } }, "at": [[0, 0]], "d": 10 }
  ] }
```

- 这里 `btn` 不写 `part` 也行：孔只碰到上盖。写上以后，意图更清楚。
- 如果再在四角打 M3 螺丝孔，并且一直穿到底壳，就不写 `part`。按默认规则，孔会穿过两个零件。

## 显示与交互

- **拆件这一步**：回滚到 `split` 时，两个零件已经分色，切面按「新增」标蓝。
- **零件行**：指向某个零件，高亮这个零件；点眼睛按钮，隐藏或显示它。
- **爆炸**：
  - 拖动滑块，零件沿上面规则算出的方向分开。
  - 松手时，视图自动取景，把分开的零件都框进来，和拆解页一样。
  - 关掉面板时，零件回到装好的位置。
- **标注**：点到的面会带上零件名，发给助教的是「上盖 · 平面 · 来自 拆成底壳和上盖」。

## 特征分解（选做）：先不做

- **它是什么**：单个零件按特征「炸开」，每一步加的料、去掉的料各成一块，悬在旁边。
- **价值**：一眼看出零件由哪几块组成。
- **代价**：
  - 每一步要多做两次布尔：「这一步之后减去之前」得到加的料，「之前减去之后」得到去掉的料。
  - 圆角、倒角会切出很多细条，抽壳会剩下一整块内腔，都很难看懂。
  - 刻字会碎成上千块。
- **已有的**：回滚已经能逐步看建模过程，而且这一步新加和改动的面会分别标成蓝色、橙色。
- **建议**：不做完整的特征分解。以后可以做一个便宜的版本：回滚到某一步时，把这一步的「工具体」画成虚影，加料是实心的浅色，切除是半透明的。内核已经为阵列和镜像存下了每一步的工具体（`Step.tools`），不用再做布尔，拉伸、旋转、孔、扫掠、放样、阵列都能用上。

## 可行性（探针：`app/.tmp/fork-parts-probe.ts`、`fork-parts-probe2.ts`）

- **平切**：用 `BRepAlgoAPI_Splitter` 在 z=20 处切开一个抽壳的盒子（80×50×30，壁厚 2，竖边 R4）。用时 27 ms，得到 2 块：z 0–20 的体积 16859.11，z 20–30 的体积 4936.99，加起来 21796.11，和原来的体积完全相等。
- **用大盒子求差、求交代替平切**：结果相同，用时 57 ms。
- **台阶形分界面**（带 1 mm 唇边，就是二期止口的做法）：用时 110 ms，两块的体积加起来守恒。
- **平面同时切过底板和凸台**：3 ms。
- **多零件 STEP**：`exportSTEP` 用时 46 ms，文件里有「底壳」「上盖」两个 PRODUCT。
  - 中文名直接写成了 UTF-8。STEP 标准要求非 ASCII 字符转义成 `\X2\…\X0\`，导出时要转换，并在 FreeCAD 里打开验证。
- **zip**：项目里还没有 zip 库。

## 分期

  - 用平面拆件，`part` 字段和默认规则；

  - 时间够的话加 3MF。

- **以后**：装配约束、零件运动、装配图和 BOM。

## 验收

- **单元测试**：
  - 抽壳盒子在 `Hs` 处拆开：两个零件的体积加起来等于原体积；零件名按法向一侧分配；改 `Hs` 以后，两个零件的高度跟着变；
  - 切面没碰到实体时报错，并写出实体的范围；
  - 写了 `part: "上盖"` 的孔，只改上盖；不写 `part` 的贯穿孔，两个零件上都有；
  - 加料碰到两个零件时报错；有两个零件、抽壳没写 `part` 时报错；
  - 圆角选中的边分属两个零件时，分别做，都成功；
  - 选择器写了 `part` 时，只在这个零件里选；候选的描述带零件名；
  - 回滚到拆件之前，只有一个零件；
  - 爆炸向量：一刀时，下面的零件不动，上面的沿 +Z 移动；两刀的杆，三段依次排开；
  - 导出：STEP 里有两个 PRODUCT，名字已转义；zip 里有两个 STL；build123d 导出含 `split(` 和 `Keep.TOP`。
- **冒烟测试**：打开一个带拆件的模型，特征树顶部出现两个零件；拖动爆炸滑块，上盖抬起来；导出 STL 时下载到的是 zip。
- **真模型评测**：
  - `split-enclosure`：「做一个 80×50×30 的封闭外壳，壁厚 2，在离底 20 mm 处拆成底壳和上盖，上盖顶面中间开一个 ⌀10 的按键孔」。检查：两个零件，名字对；底壳高 20；孔只在上盖上；两个零件的体积加起来，等于外壳去掉内腔、再去掉孔。
  - `split-long`：「一根 300×20×20 的方杆，打印机最长 200，从中间拆成两段」。检查：两段，各长 150。
  - 原有 17 道不退步。
- **浏览器实测**：在 `split-enclosure` 的结果上拖动爆炸滑块；导出 STEP，在 FreeCAD 里打开，能看到两个带名字的零件。

## 风险

- **默认规则猜错**：例如学习者只想在上盖打孔，结果孔穿到了底壳。缓解：摘要写出作用到了哪几个零件（「切除 · 上盖、底壳」），助教看得到也能改；提示词让助教在有零件时尽量写 `part`。
- **速度**：多零件时，布尔和圆角要按零件分别做，用时乘以零件数。通常只有 2 个零件，影响很小。
- **STEP 里的中文名**：不转义的话，有的软件会显示乱码。导出时转义，并用 FreeCAD 验证；如果仍有问题，就退回 `part_1` 这种名字，把中文写进描述里。
- **爆炸时的坐标**：点选和测量必须换算回装好的位置，否则 `near` 和标注的位置会偏。单元测试里专门覆盖。
- **提示词变长**：只加两句，用评测守住原有的题。
