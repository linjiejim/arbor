- 状态：已实现，待上线（2026-11-07，一期）。
  - 和方案不同的一处：`/studio/s/*` 的 noindex 不改 Caddy，由页面在 `<head>` 里动态加 `<meta name="robots" content="noindex">`，接口 `GET /api/studio/share/:id` 另带 `X-Robots-Tag: noindex`。
  - 快照里暂时没有需求核对项：核对表还没做。
- 日期：2026-11-07
- 范围：
  1. 把当前模型生成一个链接，别人打开就能看到同一个模型；
  2. 打开链接后只读查看，可以「复制到我的工作台」接着改，或导出 STEP / STL；
  3. 导入特征树 JSON（菜单或拖进视图）。
- 不在范围：账号、多人同时编辑、评论。
- 相关：`app/src/studio/use-studio.ts`（特征树和撤销存在 localStorage）、`app/src/studio/use-studio-chat.ts`（对话存在 localStorage）、`app/server/index.ts`、`app/server/limits.ts`、`app/src/routes/studio.tsx`（导出菜单）、`app/src/studio/codegen.ts`

## 为什么

- 方向定的是「AI 建，人看懂，人做定向修改，再导出、分享」。现在只能导出文件：STEP 要有 CAD 软件才能打开；JSON 能导出却不能导入，收到的人用不上。
- 特征树本身就是最好的分享物：带参数说明和每一步的设计意图，比一个 STEP 文件更能讲清楚「怎么建的、为什么这样建」。
- 现在模型和对话只存在这个浏览器的 localStorage 里，服务器不存对话，换台电脑就没了。分享链接也顺带解决「换台电脑接着改」：自己发给自己。

## 已定的建议

| 问题 | 建议 | 理由 |
| --- | --- | --- |
| 存在哪 | 服务器存一份快照（`STUDIO_DATA_DIR/shares/`），不是把特征树编码进网址 | 带对话时网址会太长；服务器存才能删除、清理、限额 |
| 快照里有什么 | 标题、一句说明（可选，≤ 200 字）、特征树（参数、参数说明、特征及其名字和意图）、需求核对项（若已做核对表）、可选的对话文字、创建时的程序版本 | 只放看懂和复现模型要用的东西 |
| 快照里绝不能有什么 | 学习者自己填的 DeepSeek key（`ft-studio-deepseek-key`）和任何 localStorage 原样内容；对话里的图片、思考过程、工具调用的原始输入输出 | 快照按白名单逐字段构造，不从 localStorage 整体拷贝 |
| id | 10 位 base62 随机串（约 59 位随机性），由 `crypto.randomBytes` 生成 | 不可猜；不按顺序编号，免得被挨个翻 |
| 有没有账号 | 没有。创建时另给一个删除口令，只存在创建者浏览器里（服务器只存它的哈希） | 不用登录也能撤回误发的链接 |
| 谁能看 | 知道链接的人都能看；不列出、不能搜；`/studio/s/*` 返回 `X-Robots-Tag: noindex` | 和网盘的「知道链接即可查看」一样 |
| 打开后能不能改 | 能临时拖参数、回滚看每一步，不保存；顶部一行提示「这是分享的模型，改动不会保存 · 复制到我的工作台」 | 拖一拖参数是看懂模型最快的办法；保存走复制 |
| 复制到我的工作台 | 直接替换，可以撤销：原来的模型进撤销历史，右上角提示「已替换当前模型 · 撤销」；对话不清空，插一条分隔「—— 换成了分享的模型「法兰盘」——」 | 可撤销的操作不弹确认；助教每条消息都带着当前特征树，旧对话不会让它弄错 |
| 分享的对话 | 只做回放，不带进自己的对话 | 别人的对话不该算进自己的上下文和花费 |
| 导入 | 「导出」菜单旁边加「导入特征树（JSON）…」；也可以把 `.json` 拖进视图。校验通过后直接替换，可以撤销；校验失败在原处说明哪里不对 | 导出的东西要能导回来 |
| 导出的代码 | 来自别人的特征树，导出 build123d 代码前必须加固（见「安全」） | 分享以后，特征树不再只是自己或助教写的 |

## 交互

1. **分享**：顶栏「导出」旁边加「分享」。点开一个短对话框：
   - 标题（预填第一个特征的名字或「我的模型」）、说明（可选）；
   - 勾选框「附上和助教的对话（只含文字）」，下面一行灰字写会带上几条消息；
   - 主按钮「生成链接」。
   - 生成后对话框里显示链接和「复制链接」；下面有「删除这个链接」（删除前确认，删除不可撤销）。
2. **打开链接** `/studio/s/:id`：和工作台同一个布局，只读。
   - 左侧特征树可以悬停看详情、单击回滚，没有编辑卡片；
   - 右侧「参数」照常显示说明和用处，可以临时拖；若「尺寸标在模型上」已做，尺寸同样显示；
   - 右侧「对话」换成「说明」：标题、说明，以及勾选了才有的对话回放（没有输入框）；
   - 顶栏：「复制到我的工作台」（主按钮）、「导出 STEP / STL」。
   - 链接不存在或已删除：页面写「这个链接不存在或已被删除」，给一个「去工作台」。
3. **导入**：选文件或拖进视图 → 校验 → 替换并提示「已导入「法兰盘」· 撤销」。失败时弹出说明，例如「第 3 个特征（拉伸1）缺少 sketch 字段」，不自动消失。

## 服务器接口

都挂在现有的 Hono 服务（`app/server/index.ts`）上：

| 接口 | 说明 |
| --- | --- |
| `POST /api/studio/share` | 请求体 `{ title, note?, tree, checks?, chat? }`；返回 `{ id, url, deleteToken }` |
| `GET /api/studio/share/:id` | 返回快照；顺带把「最后打开时间」更新到今天（一天最多写一次） |
| `DELETE /api/studio/share/:id` | 头里带 `x-share-token`；对上哈希才删 |

- **校验**：`id` 先用正则 `^[0-9A-Za-z]{10}$` 校验，再拼路径。特征树用 `Tree.safeParse`；标题、说明、对话都是纯文字，对话只收 `{ role: "user" | "assistant", text }`。
- **大小上限**：
  - 请求体 ≤ 512 KB（`bodyLimit`）；特征树 ≤ 200 KB，对话 ≤ 300 KB、≤ 200 条；
  - 特征 ≤ 200 个，参数 ≤ 100 个，任何字符串 ≤ 500 字。
  - 超了返回 413，提示「模型太大，不能分享」。
- **限速**（按 IP，复用 `RateLimiter`）：创建 20 次每小时，打开 300 次每小时，删除 60 次每小时。超了返回 429，写清几分钟后再试。
- **兜底**：请求体里出现形如 API key 的字符串（`sk-` 开头的长串）就拒绝，提示「内容里像是有密钥，已拒绝分享」。客户端本来就不会放进去，这里防万一。

## 存储与清理

- 一份快照一个文件：`STUDIO_DATA_DIR/shares/<id 前两位>/<id>.json`。线上是 `/root/featuretree/api/data/shares/`，和 `budget.json` 同一个目录，发布时不会被覆盖。
- 格式：

```json
{
  "v": 1,
  "id": "a8Kq2ZtR0x",
  "created": "2026-11-07T08:00:00Z",
  "app": "2576e89",
  "title": "法兰盘",
  "note": "第三课作业",
  "tree": { "params": {}, "paramNotes": {}, "features": [] },
  "checks": [],
  "chat": [{ "role": "user", "text": "做一个法兰盘……" }],
  "deleteHash": "sha256:…"
}
```

- 「最后打开时间」用文件的修改时间表示，打开时若早于今天就更新一次。
- **清理**：服务启动时和每天一次，扫描 `shares/`，删掉一年没打开过的（按待确认第 2 条的结论）。
- **总量上限**：2 GB。超了不再接受新分享（返回 503，提示「分享空间满了，稍后再试」），并在日志里报警。
- **备份**：不单独备份，丢了只是链接失效；`data/` 目录本来就在发布目录之外。

## 监控

- 服务日志每次创建、打开、删除记一行（id、大小、IP 的哈希），不记内容。
- watchtower 已经盯着 `featuretree-api` 进程和 5xx。再加一项：`/root/featuretree/api/data` 的磁盘占用，超过 1 GB 报警。
- 每日运维早报里加一行「分享：新建 N 个、打开 M 次」。

## 安全

- **加载时校验**：浏览器拿到快照后再用 `Tree.safeParse` 校验一次，并套用和服务器同样的上限。内核重建时，阵列个数之类可以写表达式的数，算出来以后要设上限（例如 ≤ 500），超了这一步报错，不让一个链接卡死别人的浏览器。
- **防 XSS**：
  - 对话回放用现有的 `react-markdown`（不开原始 HTML，默认会过滤 `javascript:` 链接）；
  - 标题、说明、特征名、意图、参数说明一律当纯文字渲染；
  - 不用 `dangerouslySetInnerHTML`。
- **导出代码要加固**（一期必须做）：
  - 问题一：`codegen.ts` 现在把参数和数值里的表达式原样写进 Python。
  - 问题二：特征名、意图、参数说明写进 `#` 注释时，没有去掉换行。
  - 以前特征树只来自自己或助教，问题不大；分享以后，打开别人的模型再导出代码运行，就有风险。
  - 修法：
    - 表达式先用 `expr.ts` 的解析器解析，只输出解析后重新生成的表达式（数字、参数名、运算符、白名单函数）；解析不了的不导出，并说明是哪个字段；
    - 注释和字符串里的换行、回车替换成空格；字符串一律用 `JSON.stringify` 转义。
- **密钥**：快照按白名单构造，见「已定的建议」；单元测试确认 localStorage 里有 key 时快照里也没有它。

## 分期

- **一期（本方案，约 3 天）**：
  - 生成链接（标题、说明、可选对话）、删除链接；
  - 只读查看（可临时拖参数、回滚、对话回放）、复制到我的工作台（可撤销）、导出 STEP / STL；
  - 导入 JSON（菜单、拖放）；
  - 导出代码加固；服务器上限、限速、清理、监控。
- **二期**：
  - 「我的模型」（本机多个模型）；
  - 「我分享过的」列表；
  - 链接预览图（发到微信、飞书时显示模型缩略图）。

## 验收

- 单元测试：
  - 快照只含白名单字段：localStorage 里放了 key、对话里有图片和工具调用，快照里都没有；
  - 超过上限的特征树、超长字符串、格式不对的特征树被拒绝，并说明原因；
  - 导出代码：意图里有换行时，导出的仍然只有一行注释；解析不了的表达式不会原样出现在代码里，并给出说明；
  - 服务器：创建 → 打开 → 删除往返；错的 id 返回 400，不存在的返回 404；口令不对删不掉；超速返回 429，超大返回 413；清理只删一年没打开的。
- 冒烟测试（用 mock 模型的服务）：
  - 建出小盒子 → 分享 → 在新的浏览器上下文里打开链接：模型、特征树、参数说明都在，拖参数后模型变化，刷新后恢复原样；
  - 复制到我的工作台：特征树被替换，撤销一次就回到原来的模型；
  - 导入一个 JSON 文件：模型重建；导入一个坏文件：原处说明错误，模型不变。
- 浏览器实测：线上分享法兰盘，用手机打开链接能看、能拖参数。

## 风险

- **特征树格式以后会变**：旧链接可能解析不了。特征树格式只增不减，保持向后兼容；快照记着程序版本。实在解析不了时，页面写明原因，并给「下载原始 JSON」。
- **被拿来存垃圾**：靠大小上限、按 IP 限速和总量上限兜住；日志能看出异常。
- **恶意特征树**：靠校验、上限、内核里的个数上限和导出代码加固。这是本方案必须一起做的部分，不能拆到二期。
- **对话里的隐私**：默认不带对话；对话框里写明会带上几条消息。
