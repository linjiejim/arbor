# Arbor：工具第二轮——更省、更稳、能装配、有标准件和真螺纹

- 状态：已实现（分支 feat/arbor-agent-tools-round2，待合并）
- 日期：2026-11-08
- 范围：Jim 在 0.3.1 上让 agent 建一个带盖子的盒子，盘点出的问题和缺口，这一轮全部做完：
  1. **工具定义精简**：MCP `tools/list` 从约 24 万字符降到约 8 万。
  2. **建模时绊住 agent 的几处**：刻字误报碎面、共享参数被当成「文件被直接修改」、`of` 选不到时不说原因、倒圆角选不到「外轮廓」、窄缝和薄壁没人提示、特写一个平面时取景别扭。
  3. **性能**：每个零件留一个内核（切换零件不重建）；文字特征自动留在最后。
  4. **真实螺纹几何**（`thread`）。
  5. **标准件库**（螺钉、螺母、垫圈、热熔螺母）并进零件清单；热熔螺母孔。
  6. **装配里贴合摆放**（`mates`）。
- 不在范围：装配约束求解和运动、钣金、曲面加厚、细牙和英制螺纹、螺钉上画真实螺纹、网页助教用上这些新能力（只共用特征树格式）。
- 相关：`docs/specs/2026-11-07-arbor-agent-modeling.md`（装配、共享参数）、`docs/specs/2026-11-07-arbor-desktop.md`、`desktop/README.md`。

## 为什么

用 0.3.1 建一个 80×50×30 的盒子和盖子（盖子用平移摆放，四角螺丝孔），遇到的事：

| 发生了什么 | 原因 | 这一轮 |
| --- | --- | --- |
| 刻 "ARBOR" 总有 ⚠「生成了 2 个极小的面」 | R 的腿和碗是两笔，3D 合并后交汇处留下约 0.014 mm 宽的侧壁 | 工具体自己就有的碎面不算 |
| 改共享参数后，下一步结果说「文件被直接修改」 | 零件里写的 `../x.params.json` 没有算出 `..`，和引擎写的路径对不上；内容没变的保存也触发重建 | 路径归一化；按内容判断，记下是谁写的 |
| 螺丝柱顶面和口沿齐平，`of: "boss"` 选不到 | 共面的面合并成一个，记在先生成它的特征名下 | 报错说清楚，并告诉它满足其余条件的面记在谁名下 |
| 盖面外缘倒圆角，`not: {kind: circle}` 连 R4 转角弧也排除了 | 没有「外轮廓」的说法 | 选边加 `outer` |
| 螺丝柱离侧壁 0.5 mm，没有任何提示，看图才发现 | 只检查了「没接上」（柱子接在底板上） | 每步提示窄缝（< 1 mm）和薄壁（< 0.8 mm） |
| 盖子只能手算 `at: [0, 0, H]`，螺丝更没法摆 | 装配只有平移和旋转 | `mates` 贴合；标准件 |
| 「做不到真实螺纹」 | 只有装饰螺纹 | `thread` |
| agent 每次会话先吃掉 24 万字符的工具定义 | 选择器在每个用到的地方展开，`set_tree` 展开整棵树 | `$defs` + `$ref`；`set_tree` 只说明写法 |

## 已定的决定（2026-11-08，Jim：「都修掉，一起做，本地验证好，提交一个 PR」）

| # | 问题 | 决定 |
| --- | --- | --- |
| 1 | 工具定义怎么瘦 | 生成 JSON Schema 后，把和选面、选边、基准面一模一样的子树换成 `$ref`，每个工具自带 `$defs`；字段说明全留。`set_tree` 的 `tree` 只写说明，引擎仍用完整的 zod 校验。Claude Code、Codex 都实测能用 |
| 2 | 窄缝、薄壁的阈值 | 窄缝 < 1 mm（对面的面、中间是空的）；薄壁 < 0.8 mm（中间是料）。只提示不拦截；只看平面和圆柱面，先按精确曲面筛，全套测试多约 2 秒 |
| 3 | 「文字放在最后」做成什么 | 不写 `after` 加的特征自动插在末尾那串文字特征前面，结果里说一声；写了 `after` 照办 |
| 4 | 每个零件的缓存 | 内核线程里每个零件一个 Kernel（最近 4 个），切回来不重建；被挤掉的下次用时重建；线程换新只重放当前零件 |
| 5 | 螺纹怎么建 | 不用「沿螺旋扫掠 + 布尔切除」（实测 OpenCascade 里经常整根轴被切掉或没切到）。改成：螺纹杆截面沿轴扭转拉伸（面数和圈数无关）→ 做成环 → 实体让出同样的环形空间 → glue 并进去。体积和 ISO 基本牙型差 < 0.5% |
| 6 | 螺纹面网格太大 | 显示网格先用粗角度（0.5 rad）试；三角形超过 3 万（螺纹）就用粗的，普通零件照旧用细的（0.2 rad）。M8×20：54 万三角形 / 9.7 秒 → 8 万 / 1.4 秒 |
| 7 | 标准件放哪 | `component` 加 `standard`（不写 `file`），ISO 公称尺寸（4762、7380、10642、7045、4032、7089），热熔螺母按 Ruthex / CNC Kitchen 标准款（开孔 M2 3.2、M2.5/M3 4.0、M4 5.6、M5 6.4、M6 8.0，深 = 长 + 1）。螺钉上的螺纹画成光杆 |
| 8 | 贴合是什么 | 不是约束求解：按顺序一条条满足，后一条只在前面留下的自由度里动（贴合留下平面内滑动和绕法向转；同轴留下沿轴滑动和绕轴转）。`to.face` 选中几个不共面 / 不同轴的面就放几份（一个孔一颗螺钉）；共面的面算一个 |
| 9 | 在装配里改零件时其他零件放哪 | 内核把装配建一遍（零件有缓存）拿到每个零件的最终位置，含贴合；引擎不再自己按 `rotate` / `at` 算 |

## 验证

- 单元测试：14 个文件、328 项（新增：工具定义大小和 `$ref`、set_tree 仍严格校验、共享参数不误报、碎面、窄缝 / 薄壁、`outer`、`of` 的原因、平面特写、文字自动排后、零件内核缓存、螺纹（外 / 内 / 间隙 / 报错）、贴合数学、热熔螺母孔、盖子贴合 + 四颗沉头螺钉 + BOM、在装配里改零件时看到按贴合放的垫圈、标准件报错）。
- `desktop/scripts/smoke-mcp.mjs`（官方 MCP 客户端，无窗口）通过。
- 真 agent 端到端：从源码构建的 App，Codex（gpt-6-astra）只连这个 MCP 服务，按一段中文需求建盒体、盖子、贴合、标准件、螺纹样件并导出 BOM，结果见 PR 描述。

## 已知局限

- 贴合按顺序算一次，不会反过来调整前面的零件；改了被贴的零件，后面的零件跟着重新算。
- 一个螺纹要几秒（M8×20 约 3 秒几何 + 1.4 秒网格），面也多：放在最后。build123d 导出省略螺纹。
- 标准件只有公制粗牙 M2–M12；半圆头、沉头没有 M2、M2.5（ISO 里没有）。
