## 为什么

- **两个名字**：网站叫 FeatureTree，桌面 App 叫 Arbor。现在两边是同一套内核、同一种文件格式，应该是一个产品。
- **旧 logo**：网页图标是三行特征挂在树干上，桌面图标是 3D 的阶梯轴。两个不一样，缩小后也都不好认。
- **两端定位不清**：网页工作台和桌面窗口几乎一样重。网页面对学习者，应该更轻、更贴合课程；桌面面对干活的人，应该更强。
- **说明文字太多**：工作台和窗口里有很多大段说明，比如欢迎页三个步骤加一段话、空状态的长句、顶栏的模型名，把界面挤得很满。
- **组合不方便**：窗口里「新建」只能建单个零件；装配只能让 agent 建；左栏是「打开过的文件」，不是项目；装配视图里零件列表出现两遍，上面还浮着一个「改 xx」横幅。

## 1. 改名为 Arbor

### 名字怎么用

- 产品统一叫 **Arbor**：
  - 网站标题是「Arbor · 工业建模互动课」。
  - 桌面 App 也叫 Arbor；网页上需要区分时写「Arbor 桌面版」。
  - 网页工作台就叫「工作台」，去掉原来的「AI 建模工作台 Beta」。
- 「特征树」是概念，保留：特征树那节课，以及文案里讲概念的「特征树」都不动。
- 名字的来历写进 README：arbor 既是「树」，对应特征树；也是机加工里夹着刀具转的「心轴」。

### 迁移顺序（网站不中断）

1. **先准备服务器**：
   - 把静态站当前版本硬链接复制到 `/srv/arbor/releases/<sha>`，并建好 `current`。
   - API 迁过去：停旧进程，同步数据和密钥，按新配置起 `arbor-api`。中间停几秒。
   - Caddy：新增 `arbor.linjiejim.com`；`featuretree.linjiejim.com` 也指向新目录，**先直接提供站点，不跳转**，因为这时新域名还没有解析。
2. **合并 PR**：部署工作流按新路径发布。健康检查用旧域名加 `-L`：DNS 生效前直接返回 200，切成跳转后跟着跳到新域名，两种情况都能检查到。
3. **GitHub 仓库改名**，本地 remote 改成新地址。
4. **打 tag，发布 0.3.0。**
5. **Jim 加好 DNS 之后**，把旧域名切成永久跳转。命令写在 `docs/deploy.md`，切换前先确认新域名的证书已经签好。
6. **一周后删旧目录。** 命令写在 `docs/deploy.md`。

## 3. 界面减法

### 灰色 ⓘ（`Hint`）和导览（`Tour`）

- **`Hint`**：
  - 一个灰色的 ⓘ 图标按钮，平时是浅灰色，鼠标放上去变深。
  - 点开是一张小卡片，一次显示一条说明，下面有页码「1/3」和「上一条」「下一条」；到最后一条，按钮变成「知道了」。
- **`Tour`**：把一个页面上的各个 `Hint` 按编号串起来。
  - 第一次打开这个页面时，自动打开第 1 个 ⓘ；一个 ⓘ 的最后一条按「下一条」，就跳到下一个 ⓘ。
  - 随时可以「跳过导览」。
  - 看完或跳过之后，在 localStorage（`arbor:tour:<页面>`）里记一下，以后不再自动弹出；再点任何 ⓘ，都只看它自己的几条。
  - 导览中的 ⓘ 如果当时不在屏幕上（比如在另一个页签里），就跳过它。
- **写文案的规则**：
  - 面板上只留标题和控件。
  - 空状态只写一句话，加一个按钮。
  - 解释性的句子都进 ⓘ：为什么这样、怎么用、技术细节。
  - 每条说明不超过 40 个字。

### 网页工作台

| 现在 | 改成 |
| --- | --- |
| 顶栏「AI 建模工作台」「Beta」，加上模型名 `deepseek-…` | 「工作台」；模型名放进对话页的 ⓘ |
| 「3D / 工程图」切换、代码页签、导入、自己的 key 分散在顶栏和页签里 | 都收进顶栏的「⋯ 更多」菜单：工程图、代码、导入特征树、使用自己的 key |
| 右侧三个页签：对话、参数、代码 | 两个页签：对话、参数 |
| 对话页开头的「用说的来建模」加一段说明 | 只留标题，说明放进 ⓘ（三条：怎么描述、能回滚和拖参数、内核在浏览器里算） |
| 参数页开头的一行说明 | 放进 ⓘ |
| 视口上方的提示「单击模型上的面或边，标注要改的地方」 | 放进导览的一条，平时不显示 |

## 4. 桌面：以项目为单位

### 什么是项目

项目就是一个文件夹，不加项目文件。项目根这样确定：

1. 窗口里「新建项目…」「打开项目…」，或者 agent 调用 `open_project`，明确指定一个文件夹。
2. 打开一个装配文件：项目根是装配所在的文件夹。
3. 打开一个零件：
   - 零件已经在当前项目里，就不变。
   - 否则往上找最近一个含 `*.arbor-asm.json` 的文件夹，最多找 3 层，不超过用户主目录。
   - 找不到，就用零件所在的文件夹。

**扫描**：

- 从项目根往下扫 3 层，跳过 `.` 开头的文件夹和 `node_modules`。
- 收集 `*.arbor.json` 和 `*.arbor-asm.json`，最多 300 个。
- 读出每个文件的特征数，按修改时间缓存，文件没变就不重读。
- 打开、新建文件之后，以及窗口重新获得焦点时，重新扫一遍。

### 新建项目

在选的位置建一个文件夹 `<名字>/`，里面放：

- `<名字>.arbor-asm.json`：空装配，`uses` 指向下面的参数文件。
- `<名字>.params.json`：空参数。

然后打开这个装配。

### 往装配里加零件

装配视图的特征树底部有一个「+ 零件」菜单：

- **新零件…**：
  - 输入名字后，建 `parts/<名字>.arbor.json`，它的 `uses` 指向项目的参数文件。
  - 在装配里加一个引用它的 `component`。
  - 然后进入「在装配里编辑」这个零件。
- **已有零件或装配…**：文件对话框选一个文件，加一个 `component`。
- **STEP 参考件…**：文件对话框选 STEP，加一个 `component`。

这几个都是普通的改动，记在动态里，能撤销，改动人记为 user。

### 装配视图

- 特征树里，每个零件占一行，行上有：
  - 眼睛：显示或隐藏这个零件的全部实体。
  - 「改」：在装配里编辑这个零件。
- 去掉特征树上面那份多零件的显示列表，也去掉浮动的「装配 · N 个零件 / 改 xx」横幅。
- 在装配里编辑某个零件时，顶部留一条细横幅：「在 pen 里编辑 笔头 · 回到装配」。

### 左栏

- **有项目时**：
  - 标题是项目名（文件夹名），旁边是「新建零件」「打开…」两个按钮。
  - 下面分「装配」「零件」两组，每个文件一行：名字、特征数，有未处理备注的写出条数。点一下打开。
  - 打开着、但不在项目里的文件，放在最后一组「其他」。
  - 「新建零件」建在 `parts/` 下，不自动放进装配。要放进装配，用装配视图里的「+ 零件」。
- **没有项目时**：和现在一样，列出打开着的零件。
- **菜单「文件」**：新建项目…（⇧⌘N）、打开项目…（⇧⌘O）、新建零件…（⌘N）、打开…（⌘O）、打开最近。

### agent 这边

- **新命令 `open_project`**：
  - 参数：`path`（文件夹），`create`（为 true 时建出上面的骨架）。
  - 返回项目里的装配和零件清单。
  - 有了它，agent 就有 39 个工具。
- **`list_parts`**：改为列出当前项目里的全部装配和零件，并标出哪些是打开着的；没有项目时和现在一样。
- **提示词**加一条：多个零件组成的东西，先 `open_project`（加 `create: true`），零件放在 `parts/` 下，共用的尺寸放进项目的参数文件。
- **命令行**：`arbor call open_project path=pen create=true`。

## 5. 网页：练习场

### 练习

- **数据**：放在 `app/src/content/practice.ts`。

  ```ts
  type Practice = {
    id: string            // "revolve-1"
    lesson: string        // 课程 id，如 "revolve"
    title: string         // 「车一根阶梯轴」
    task: string          // 一两句话的任务，写清楚尺寸
    start?: Tree          // 起始特征树；不写就是空的
    checks: Check[]       // 判分用的要求，id 以 "p-" 开头
    tips: string[]        // 提示，放进练习卡的 ⓘ，按顺序翻
    solution: Tree        // 参考答案：只给测试用，界面上不显示
  }
  ```

- **入口**：
  - 有练习的课程，课程页末尾放一张「去工作台练一练」的卡片。
  - 工作台的地址是 `/studio?practice=<id>`。
- **工作台**：对话页顶部固定一张练习卡，内容有：
  - 题目和任务。
  - 每一项要求，随着重建实时打勾。
  - ⓘ：提示，按顺序翻。
  - 全部通过后，显示「完成」，并记进学习进度 `practice:<id>`；课程页的卡片也显示「已完成」。
  - 「退出练习」：练习卡收起，模型留着。
- **判分**：
  - 练习的要求存在特征树的 `checks` 里。
  - 学员或助教把它删掉、改掉了，下一次重建时按 id 自动补回原样。
  - 助教另外加的核对项照常保留。
- **第一批**：8 道练习，覆盖草图到实体、旋转、阵列与镜像、圆角与倒角、圆角与抽壳的顺序、扫掠与放样、基准面、3D 打印悬垂。
- **验收**：
  - 每道题的参考答案在单元测试里用真内核建出来，要求全部通过。
  - 起始状态下，要求至少有一项不通过。

### 术语

- 「边做边学」时，助教回复里某个术语（`terms.ts` 里有的）第一次出现，就变成可以点的，样式和课程里的术语一样。
- 点开是解释卡片，带「在术语表里看」的链接。
- 一条回复里每个术语只标第一次。

### 桌面版介绍页 `/desktop`

- 内容：一句话介绍，三条能力（agent 通过 MCP 建模、项目和装配、导入 STEP 和核对），下载按钮（Apple 芯片 / Intel，指向 GitHub Releases 的 latest），以及第一次打开时怎么放行。
- 页眉加「桌面版」，首页在工作台那一节旁边加一个入口。

## 风险

| 风险 | 对策 |
| --- | --- |
| DNS 没加之前，新域名打不开，而 canonical 已经指向新域名 | 旧域名继续直接提供站点；DNS 生效、证书签好以后，再把旧域名切成跳转 |
| 仓库改名后，有人新建同名仓库，转发就断了 | 不再建 `featuretree` 仓库，写进 README |
| 迁移 API 时停几秒，这期间写入的分享可能丢 | 先停旧进程，再同步数据；在访问量最低的时候做 |
| 学员删掉了练习的要求 | 重建时自动补回 |
| 项目扫描遇到很大的文件夹（比如在主目录上打开） | 限制 3 层、最多 300 个文件，跳过隐藏文件夹和 `node_modules` |

## 实现中发现的问题

| 问题 | 处理 |
| --- | --- |
| 浏览器里存工作台数据的键是 `ft-studio-*`（模型、对话、自己的 key、分享令牌） | 不改：改了要逐个迁移，用户看不到这些名字。只有学习进度的键带着完整的旧名字，迁到 `arbor:progress` |
| 第一版 logo 的拉伸面上有一道白缝 | 竖干顶边和弯钩接缝处多出一段 0.01 的边，扫掠面没并上。改成两者正好共边，扫掠前去掉重复的边 |
| 导览从第 1 个 ⓘ 切到第 2 个时，整段导览就结束了 | 第 1 个弹层关闭时把焦点还给自己的按钮，第 2 个弹层把这当成「焦点移到了外面」就关掉了。导览中不再归还焦点，也不因焦点移出而关闭 |
| 桌面版第一次启动时还没有打开文件，导览只走左栏一条就记成看过了 | 导览等有内容（网页：内核就绪；桌面：打开了零件）再开始 |
| 往装配里放一个刚建的空零件，装配报「一步都没有建成」 | 空零件当占位：不报失败，给一条 ⚠「还是空的」 |
| 开发服务器上 `/desktop` 打开的是桌面窗口的页面（`desktop.html`） | 只影响开发：Vite 加一个小插件把 `/desktop` 交给网站；生产构建本来就对 |
| 一个原有的内核测试偶尔超过 5 秒（新增的练习测试一起跑，机器更忙） | vitest 的单个测试超时改为 30 秒 |
| 练习「把盒子的特征顺序改对」判不出顺序：顺序不改、另加一个内侧圆角，几何一样，也能通过 | 接受：练习看结果，提示里讲清顺序的作用 |
| `holes` 核对也用来数圆角的圆柱面（「4 个 ⌀10」表示 4 个 R5 圆角） | 接受；要求的原话写的是 R5，期望值写 d=10，两边读起来一致 |
| 已提交的 GLB 里 `generator` 还是旧名字 | 不重新烘焙一百多个二进制文件，下次烘焙自然更新 |
| 浏览器的本地存储按域名分开：旧域名直接 301 的话，学员在旧域名上的进度和模型就留在那边了（Codex 审查发现） | 旧域名的页面改为返回交接页 `moved.html`：读出进度、工作台模型和设置，放在网址片段里打开新域名的同一路径，新域名合并后去掉片段。接口 308、静态文件 301 直接转过去。DeepSeek key 和对话不带 |
| 新建项目时文件夹里已经有同名参数文件，会被清空（Codex 审查发现） | 已有参数文件就保留，新装配直接用它 |
| 同一个零件放进装配两次，第二个和第一个重名，装配报错（Codex 审查发现） | 自动起名「名字-2」 |
| 没写 name 的组件，「隐藏」找不到它的零件；子装配点「改」没反应（Codex 审查发现） | 组件名的推导抽到 `dsl.ts` 的 `componentName`，内核和窗口共用；子装配不带 context 打开，失败时提示 |
| 练习中助教改了练习的要求，工具结果说「全部满足」，面板却是没通过（Codex 审查发现） | 工具结果按恢复后的要求重新给，并告诉助教这些要求是固定的 |
| 术语第一次出现在代码里时，后面正文里的那次也不再可点（Codex 审查发现） | 只按正文里的出现算第一次 |
| 判断「正文里第一次出现」时，把缩进 4 格的行都当成代码，嵌套列表里的术语就点不了（Codex 第 3 轮发现） | 改用渲染时的同一个解析器（remark + GFM）取正文文字，和点亮术语的插件跳过同样的节点 |
