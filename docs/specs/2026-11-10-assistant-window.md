- 状态：已实现（2026-11-10，Jim 授权「你来主导，全部落地」）
- 日期：2026-11-10
- 范围：桌面版的内置助手从右侧页签里拿出来，成为可浮动、可固定、可收起的对话窗口；对话按轮自动保存，可以翻回去接着聊；修掉切零件丢对话、流式卡顿、长时间没反应；顶栏只留「在哪」和全局操作，状态挪到底部状态栏。
- 不在范围：整轮撤销、参考图、「测试连接」（仍在 `2026-11-10-turnery-assistant.md` 的第 4 步里）；网页工作台的对话。
- 相关：`2026-11-10-turnery-assistant.md`（助手本身）

## 为什么

Jim 用了一天之后提的五件事：

1. 对话栏挤在右侧页签里，和备注、参数抢位置。
2. 顶栏塞了太多东西（Agent 动态、版本号、视图切换、导出……）。
3. 对话会卡；有时思考很久没有任何输出。
4. 新建零件后对话没了。
5. 过去的对话没有保存，回不去。

读代码找到的原因：

- **丢对话**：对话状态在 `AssistantPanel` 里，它挂在右侧页签下，而页签只在有零件时渲染；零件切换、加载的那一刻它被卸载。
- **卡顿**：桌面版的 `useChat` 没有节流，每个流式片段都重绘整列消息、重新解析 Markdown，还 `scrollIntoView` 一次。
- **没输出**：主进程发了思考过程（`sendReasoning: true`），窗口的消息组件把 `reasoning` 部分直接丢了；状态只有一句「助手在做…」。
- 另外发现：助手的调用没有 `cwd`，模型写相对路径（`open_part parts/cup`）时会落到根目录。

## 设计

### 对话归窗口所有

`AssistantProvider`（`app/src/desktop/use-assistant.ts`）包在整个窗口外面，持有 `useChat`、当前对话的编号和标题、输入框草稿、历史列表。面板只是它的一个视图：浮动、固定、收起之间切换不影响进行中的一轮。`useChat` 节流 50 ms；`Message` 用 `React.memo`，只有正在写的那条重绘；滚动只在用户停在底部时跟随。

### 中间过程

- 思考中：思考过程实时显示最后几行（灰色、限高），结束后折叠成「思考过程」一行。
- 一轮进行时底部一行状态 + 秒数：等模型回应 / 思考中 / 正在写「做拉伸」的参数 / 正在核对需求 / 看结果，想下一步 / 正在回复（`app/src/desktop/assistant-activity.ts`）。
- 工具卡片在参数生成时就出现（转圈），带特征名。
- 每条回答下面一行用量：输入、缓存命中比例、输出 tokens（`messageMetadata` 带上 `totalUsage`）。

### 对话窗口

`app/src/desktop/assistant-layout.ts`、`ui/assistant-window.tsx`。三种状态，记在 localStorage `turnery:assistant-layout`：

| 状态 | 样子 |
| --- | --- |
| 浮动 | 浮在窗口上，拖标题栏移动，八个方向拖边改大小；最小 320×300，始终在标题栏下面、窗口里面 |
| 固定 | 右侧一列，拖左边改宽 |
| 收起 | 只剩顶栏右上角的「对话」按钮；一轮进行时按钮上转圈 |

顶栏的「对话」按钮在收起和上一次的状态之间切换。

### 对话历史

- 存在 `~/.turnery/chats/<id>.json`，另有 `index.json` 存列表（不必读每个对话就能打开列表）。最多 200 个，旧的先删。
- 一轮结束（完成、停止、出错）时保存；只是打开旧对话不会把它顶到最前。
- 存之前去掉 `look` 的图片（结果文字保留，卡片上写「N 张视图没有保存」）和没跑完的工具调用。
- 每个对话记下所在的项目和开始时的零件。历史列表默认只列这个项目的，可切到「全部」。
- 标题默认取第一句话，点标题可改名；列表里每项可删。
- 编号只接受 `c-[a-z0-9]{6,32}`，读写都在 chats 目录里。

### 顶栏和状态栏

- 顶栏：标志、首页、项目 / 零件；视图切换（3D / 工程图）；右侧撤销、重做、导出、「对话」、「接入 Agent」。版本号和 Agent 动态移走。
- 底部状态栏（`ui/status-bar.tsx`，28 px）：谁在动模型 · 内核 / 重建状态和耗时 · 核对 n/m · 后台核对中 · N 条备注待处理（点开备注页签）· 右侧「第 N 版 · 谁 多久前」。只说现状，不放操作。

## 决定

- **D1 对话存在 `~/.turnery/chats/`，不放项目文件夹。** 项目文件夹常进 git，对话里有用户的原话。原 spec 的 D5 建议「按项目一个文件、最多 80 条」，改成每个对话一个文件加索引：要能翻回任意一段，而不是只有最近的。
- **D2 浮动窗口是窗口里的浮层，不是第二个系统窗口。** 系统窗口要管焦点、置顶、跨屏，IPC 也要多一条路；浮层就够用，而且固定 / 收起都是同一个组件。
- **D3 对话状态放在窗口最外层，不放主进程。** 主进程已经负责跑一轮；让窗口持有消息，刷新窗口会丢掉进行中的那轮显示（主进程那边的调用照常完成，模型的改动都在）。代价可接受，比在主进程里再维护一份 UI 消息简单。
- **D4 状态栏不放按钮**，唯一例外是「N 条备注待处理」，因为它对应一个明确的去处。

- **D5 两个窗口续同一段对话时，后存的那份另存为副本**（Codex 审查发现）：保存时带上「我是从几条消息开始的」，文件里已经更多就不覆盖。不加锁：两个窗口同时开着同一段对话很少见，副本比报错好懂。
- **D6 固定的对话栏要给模型留至少 360 px**（Codex 审查发现）：可用宽度 = 窗口 − 零件列表（≥1024 时 224）− 右侧面板（380，<1280 时 340）− 360；不够 320 时「固定在右侧」不可点，已固定的回到浮动。
